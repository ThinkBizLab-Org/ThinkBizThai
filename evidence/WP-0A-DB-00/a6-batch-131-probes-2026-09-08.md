## Why this file exists

A static suite asserts what its own files say. The only way to find out whether a rule BITES is to
break the thing it is about and watch. Batch 140 recorded the same exercise and found two rules that
counted where they should have named; this round found two that read the wrong text.

Each probe applies one plausible regression to a committed file, runs
`node --test tests/db/identity/identity-isolation.test.mjs`, and restores the file. A probe is
**NOTICED** when the suite exits non-zero.

## The two misses, and what each one actually was

Neither was a missing rule. Both were rules reading the wrong text — the same shape of defect batch
140 recorded, arriving through a different door.

### 9. A rule about a comment that read the code with comments stripped

RFC-2026-022 §5/4 is explicit that the confinement term "is a containment control against defects in
the service's own code, not a boundary against the service role … no document, test or assertion may
cite it as tenant isolation of the service path." The **sentence beside the expression** is the thing
the decision forbids, and my assertion read `projectionCode` — the migration with `--` comments
stripped. The probe added `current_setting('app.workspace_id', true)` as a comment line and the suite
was silent.

That is not a cosmetic miss. A batch with no CARRIED cell that nevertheless carries a comment about
the GUC is exactly how the false claim spreads: the next author reads the comment, not the RFC.

**Closed with two assertions over the RAW file**, because the migration legitimately contains the
expression ONCE — RFC-2026-022 §3's operational test asks a batch to add the term to its own
statement in order to decide whether the cell is CARRIED or DISCOVERED, and the header shows that
working. So the rule is an exact count of one, plus a requirement that the header carries §5/4's
disclaimer beside it. A second occurrence is either a policy this batch may not write or a second
sentence about a control it does not have.

### 16. A fixture row whose LABEL survived while its STATE went

`fixture-billing-event-unresolved` is the row the whole DISCOVERED classification is about: a
provider event whose workspace has not been resolved, which is what §8.3 of the Stripe billing
contract initialises `correlation_workspace_id` to. The probe gave that row workspace A's id and the
suite was silent, because the assertion matched the LABEL and the label had not changed.

This is batch 140's finding in a different file — "a rule that counted where it should have named" —
and its converse: a rule that named where it should have counted. **Closed by counting the tenant
references in the receipts insert**: three receipts, TWO workspace uuids. The position of a `null`
inside a `VALUES` row is formatting; the number of tenant references is the fact.

## What these probes do NOT establish

- **Nothing here ran against a database.** `131_billing_projection.sql` has never been parsed by
  Postgres: batch 131 is declared in `not_applied_to_this_instance`, and the apply-time `do $$` block
  — which is where the column allowlist, the per-column immutability walk, the money types, the
  card-shape refusal and the foreign-key column sets are actually enforced — is therefore UNEXECUTED.
  Every claim about it in this file is a claim about text. The CI container's
  `make db-migrate-clean` is where that block first runs, and until then the strongest statement
  available is that the SQL says what the tests say it says.
- **The isolation cases have never been executed either.** `tests/db/identity/run-isolation.mjs` is a
  library with no driver, for the reason it prints when run directly. All 374 cases are data that a
  static suite reads; none has met a policy.
- **The negative control has not bitten on these three tables.** The CI step that disables row level
  security per table has not run against a database holding them, so "each entry rests on two cases"
  is a property of the case list rather than a measured failure.
- **A probe is not a proof of completeness.** Eighteen mutations is eighteen; the rules that no probe
  attacked are unmeasured, and the honest reading of "18 of 18" is that the eighteen shapes I thought
  of are covered.
