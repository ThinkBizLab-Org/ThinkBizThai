### QR1 — Medium: L's import allowlist reads one line at a time, so a multi-line import passes as L

§4.5 says the fail-closed parts include "L's imports (§4.2 item 10 (b))". The script's header says the same (lines
15-17). But `importSpecs` (`classify-review-tier.mjs:193-202`) applies its patterns to each added line separately, and
the first pattern needs `import` or `export` and `from '...'` on the **same** line. Take the shape a formatter gives any
long import list:

```
import {
  getMe,
  listOrders,
} from '@/lib/data';
```

That shape yields no specifier, so nothing is refused. M6 measured **tier L** through the CLI, end to end, for
`apps/web/components/Card.tsx` importing and calling `@/lib/data` this way (N1). The one-line form of the same import
gives H (N1b). The API gives the same result inside an allowlisted module. Of the "no data path" parts, the import
allowlist was the one the RFC presents as mechanical, and this is the commonest way data reaches a component (C0 F1).
The Reviewer's written confirmation (§4.3) is still a backstop. But the text tells the Owner that this part does not
depend on it.

Condition, either of two. (a) Imports are read over the file's added text joined, not line by line. A simpler fail-closed
alternative is that any added line holding `from '<spec>'` or `from "<spec>"` (with or without `import` on it) yields
that specifier. The test pins the multi-line shape above as not L. (b) §4.5 and the header drop "L's imports" from the
fail-closed parts. Settle it **before the Owner answers Q-030-1**.

### QR2 — Low: an event-handler attribute in mixed case passes at L

The handler signal (`:82`) is lower-case only, so that JSX's `onClick={...}` is not caught. §4.2 item 7 says "a
lower-case HTML event-handler attribute", so the text discloses it. But the HTML parser ignores the case of attribute
names. A copy string rendered as HTML anywhere (`OnError=`, N3c) and an L-path SVG that is inlined (`onLoad="..."`,
`ONLOAD=`, N3a/N3b) are both **L**. Suggestion: also flag `on<letters>` in any case when its value is a quoted string
(`/\bon[a-z]+\s*=\s*["']/i`, since a JSX handler is `={`). Pin `onLoad="..."` and `OnError=` as H, and keep
`onClick={save}` clean.

Each of the following mutants leaves the review-tier test green and makes the classifier lighter:

### QR4 — Low: neutral evidence admits an append to another role's verdict, and one foreign package's records

Q1 asked that neutral evidence be "added (or appended) under the PR's **own** package". The classifier cannot know the
PR's own package. It only checks that at most one package appears (`:336-339`), and `verify-branch-scope.mjs` compares
against the union of every package's writable paths. So an L change plus `evidence/WP-OTHER/note.md` alone is **L**
(N6). An append to an existing role verdict in the same package (`c0-review.md` + "Addendum: VERDICT approved") is also
**L** (N5). RFC-2026-025 §6.1's records path admits only named record files. Suggestion: take the package from the
branch name or from the manifest or handoff in the diff and require records to match it, and treat an append to a
`c0-`/`a1-`/`q0-`/`r0-` review file as H. Or §4.2 item 3 states both cases, so the Owner sees them.
