### Q9 — Blocking the merge: `main` (#204, E4) requires the classifier to be digested, and the fix is outside this PR's declared paths

`test-kits/integrity-manifest.json` and listed in `DIGESTED_FLOOR`. This PR's test imports
`scripts/db/classify-records-only.mjs`, which is in neither. So **any** head that contains `main` is red (N10). The
red is not limited to the digest conflicts, so `regenerate:manifest` and `record:verification` cannot fix it.
§6.6 item 2 lists "the classifier digested" as owed later. `main` now makes it a precondition of this merge.

The probe in N11 shows that this is the only cause. With the classifier digested and on the floor, the merged
suite is 725/725 and `check` exits 0. But the floor lives in `scripts/verify-test-coverage-floor.mjs`, a guard this
package neither owns nor declares as an amendment, so `verify-branch-scope` exits 73 (N12). The choice is A0's,
or the Owner's, and not mine. One way is to widen `ownership.amends_without_owning.paths` by that one file, with a
reason, and make the two-line edit in this PR. That is an ownership change and a guard edit, so it is not
records-only. The other way is to land the digest through the guard's owner first, and then merge `main` again.

Either way, the head that carries it is a code-and-guard change. This role must then re-measure the full suite at
that head, with `main` contained. So must the checks that the guard edit touches: the coverage-floor tests, the
`DIGESTED_FLOOR` ratchet and the scope check.
