## 4. Findings of this round

### A1-R1 (Low; merge condition, code or text): L's import allowlist reads one line at a time, so a multi-line import passes it

`importSpecs` matches `import|export ... from '<spec>'` within a single added line. The shape Prettier writes for any
import longer than the print width -- `import {` / `  getMe,` / `} from '../lib/data';` -- has no line that carries both
`import` and `from`, so the specifier is never seen, `lImportProblems` returns nothing, and the web component is **L**
(measured above, both for a relative import into `lib/` and for a package such as `@tanstack/react-query`). The same
function feeds `crossModuleImports`, so C0 F5's cross-module rule misses the same shape (measured M with a module
allowlisted in the probe). Only an import whose specifier happens to trip a data signal (`@supabase/`) is caught.

This matters because the RFC names L's import allowlist as one of the three parts that **fail closed** (§4.5), and §9
records A1-3 as "met by the classifier on this PR ... not further conditions". As measured, that sentence is not true of
the most common import shape. Nothing is exposed today (no `apps/` path exists, and the L Reviewer confirms "no data
path" in writing), so it is Low and not stop-the-line.

**Condition (before the merge), either:** (a) read import and export statements across lines -- for example, join a
file's added lines (or read the whole head blob of an L or module file) and match statements on the joined text, and
treat an added line that starts or ends inside an import statement whose specifier is not found as a data path -- with
the multi-line shapes above pinned in the review-tier test; **or** (b) change §9's sentence so that A1-3's import
allowlist is again a precondition before L takes effect, and §4.5 no longer calls it fail-closed until (a) lands. A1
prefers (a); it is a few lines.

### A1-R2 (Low; merge condition on the text): "an A0 run that did not author the PR" is the Author by role ID

§3.1: the merge of an M or L PR is pressed by a run that is not the PR's Author, and "under the standing delegation that
run may be an A0 run that did not author the PR". Separation of duties in this repository is by `agent_run_id`: the
manifest's `author_agent_run_id` for WP-0A-DB-00 is `/claude/a0_atlas`, the handoff's `agent_run_id` is the same, and
`validate-work-package-role-separation.mjs` compares those IDs. Another session of `/claude/a0_atlas` is the same Author
for that comparison, so the sentence lets the Author's ID press its own M or L merge -- option (b) without (b)'s
safeguards -- for every PR A0 authors.

**Condition (text):** §3.1 says "not the Author's" means an `agent_run_id` different from the PR's handoff
`agent_run_id` (and from the manifest's `author_agent_run_id`), and drops or narrows the A0 sentence to "an A0 run, when
A0 is not that PR's Author". If the Owner prefers that A0 press its own M/L PRs, that is Q-030-5 (b), and the text should
say so there, not in §3.1.

### A1-R3 (Info): the remaining misses are the denylists the RFC already names

Identifiers such as `authToken`, `sessionToken`, `idToken`, `apiToken`, `signingKey`, `encryptionKey`, `hmacKey`,
`passphrase`, `cardNumber`, and the Thai payment names `omise` and `promptpay`, raise nothing in an L web component; a URL
assembled from string pieces, `href={props.url}`, a `data:` URL, and an import of another (non-allowlisted) module's

as identifier sub-words (with `id`/`api`/`auth`/`session`/`signing`/`encryption`/`hmac` pairs), `card`, `cvv`, `pan`,
`omise`, `promptpay`, `paypal`, `2c2p`; a `data:` scheme as a data-path signal; and an import target under
`src/modules/<key>/` counting as L only when `<key>` is allowlisted. No condition.

Neutral evidence is "added or appended to". A line appended to `evidence/WP-0A-DB-00/q0-review-2026-10-07.md` in an L PR
