# Batch 041 — reversal probes, and the one they found

Run: `/claude/a2_knowledge` (A2 Knowledge), Author of batch `041`, 2026-09-06.
Branch: `agent/claude/WP-0A-DB-00-batch-041`.
Method: apply ONE reversal to a committed-shape file, run
`node --test tests/db/identity/identity-isolation.test.mjs` (and `node scripts/db/run.mjs schema-lint`
where the reversal is in the migration), record which named test refuses it, restore the file. The
script that does this is not committed; every step it takes is written out below and is
reproducible by hand.

This is the same shape batch `040` used, for the reason `040` recorded: a green suite is not
evidence until it can be made to go red on purpose, and the probes are what turn "these tests check
the batch" into "here is the edit each one refuses".

---

## What the probe round found, before the results

**A test that asserted a constant against itself.** The first version of the totality guard read:

```js
for (const guarded of ['item_business_profile_id is not null', …]) {
  assert.ok(RESOLUTION_BODY.includes(guarded), …);
}
```

`RESOLUTION_BODY` is the expected value declared five lines above it. The loop therefore compared
the constant with itself and would have passed against **any** migration, including one with no
function in it at all. It was invisible in a green run and it is exactly what the probes exist to
surface: the loop's three assertions contributed nothing, and the whole predicate rested on the
single `assert.equal` beside them.

That also exposed a **concentration**: probes P1, P2 and P3 — three independent reversals of the
predicate, each with a different failure mode — were all noticed by that one assertion. Deleting one
line would have taken all three notices with it, which is `040`'s own scar (`USING` and `WITH CHECK`
are two catalog columns, and one assertion over the whole policy body could not tell them apart)
arriving one batch later in a different shape.

**Fixed in the same change.** The section is now three tests instead of one: the whole-body pin, a
clause-by-clause test that reads the FILE (three branches, three null guards, and the eight
apply-time raises that carry the behavioural half), and the `search_path` argument with its premise.
P1–P3 are now each refused by two independent tests.

## What these probes CANNOT reach, stated rather than left to be assumed

**Nothing here executed SQL.** This host has no `psql`, no `postgres` and no container runtime
(checked: `which psql postgres pg_ctl docker initdb` finds none), and batch `041` is declared
`not_applied_to_this_instance` in `db/foundation/lint/catalog-snapshot.json` because its apply-time
block reads `app.knowledge_items`, which the provisioned instance does not have. So:

* **`041_knowledge_resolution.sql` has not been parsed by a Postgres.** Every claim above about the
  migration is a claim about its TEXT. CI is the proof surface: `make db-migrate-clean` applies all
  twelve batches to a `postgres:17` container on every pull request, and that is where the function
  body, the `do $$` block and the nine-call truth table are first executed.
* **The fifteen new isolation cases have not been RUN.** They are executable specification until
  `make db-rls-smoke` runs them in CI. Batch `040` learned this the expensive way — a case using
  `__SELF__` under an identity with no JWT subject inlined the text `'undefined'` and came back
  `22P02`, invisible to every static rule — so the claim here is deliberately narrow: the cases are
  well-formed, they are pinned by the static suite, and whether they PASS is CI's answer and not
  this file's.
* **P4's `schema-lint` result is a text rule, not a catalog one.** It reads the migration's own
  words. The catalog half — `prosecdef`, `provolatile`, `proconfig` read from `pg_proc` — is in the
  migration's apply-time block and runs only where the migration runs.

**No measurement of a query plan.** The migration's header argues that a `SET` clause would make the
predicate opaque to the planner's inliner, and says in terms that this is a design reason and NOT a
measurement. Nothing here measured a plan, and nothing here claims one.
