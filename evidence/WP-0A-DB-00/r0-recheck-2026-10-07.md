**R-9 (blocks the merge at this head; not stop-the-line). A multi-line import escapes L's import allowlist, which the RFC
names as fail-closed.** `IMPORT_SPECS` matches line by line, and the first pattern needs `import`/`export` and `from '…'`
on the same line. A formatter wraps any import longer than its print width, so the common form is
`import {` / `  a,` / `} from '../actions';`; its specifier line has no `import` keyword and is never read. Measured: four
shapes (named, `from` on the next line, `import type`, `export { … } from`) all print **L** for an `apps/web` component
whose import resolves to nothing at the head, or to an alias into `lib/`. RFC §4.5 says "the fail-closed parts are the
allowlists: … and L's imports (§4.2 item 10 (b))"; this is that part open. Today nothing is reachable (no `apps/` path;
§9 keeps every PR H until the CONTRIBUTING edits and the CI step land), so it is not stop-the-line. It is the same class as
R-1: the gate under-classifies against its own text, and the Owner would be approving that text.
**What has to hold:** specifiers read across lines (for example, the added lines of a file joined before
`IMPORT_SPECS` runs, or any `from '…'`/`from "…"` and any bare `'…';` continuation treated as a specifier), with a pinned
case per shape above; or §4.5 and §4.2 item 10 (b) say that only single-line imports are read and the Owner is told in §11.
