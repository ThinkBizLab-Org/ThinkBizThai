## 4. Findings

### A1-10 (Low; merge condition): the merge of `main` is red because the classifier is not digested, and it must be fixed by digesting it, not by loosening the guard

`main` `ae163ed8` (#204, WP-0A-A0-002) walks the import closure of every test file and refuses any module that is
not digested (E4, `open_blockers[9]`). `test-kits/db/foundation-contract.test.mjs` imports
`scripts/db/classify-records-only.mjs`, which is not in `test-kits/integrity-manifest.json`. That is RFC §6.6
item 2, which §6 listed as owed later. On `main` it is now a hard failure: `verify:coverage-floor` exits 92, and
six tests fail with the same message. The guard is right: an undigested script runs during a green check.

The fix is two lines in one commit, and both are needed. My probe shows that adding the manifest key alone makes
`verify:coverage-floor` exit 87, because a digested file must also be in `DIGESTED_FLOOR`:

1. `scripts/db/classify-records-only.mjs` in `test-kits/integrity-manifest.json`, with its real digest;
2. `scripts/db/classify-records-only.mjs` in `DIGESTED_FLOOR` in `scripts/verify-test-coverage-floor.mjs`.

The second path is owned by WP-0A-A0-002. It needs an `amends_without_owning` entry on WP-0A-DB-00 with a reason,
and WP-0A-A0-002's acknowledgement, as other packages' floor lines have had. WP-0A-A0-002 cannot do this first
on `main`, because the classifier does not exist on `main` until this PR merges.

**Not acceptable as a fix:** removing or moving the classifier import out of a digested test, exempting it in the
import walk, or any change to the E4 guard on this branch. Each would remove a control `main` just gained.

Once done, §6.6 item 2 is closed, not owed. The RFC text of §6.6 item 2 then needs one line saying so. That
is another edit to §6, so the roles re-read it.
