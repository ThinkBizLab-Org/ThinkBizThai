## 4. Are the three options described accurately and neutrally?

Yes, as general knowledge (the note says "not measured"), with no preference stated:

- **Vault + `pg_net` header.** Accurate. The exposure points named (who can read the decrypted secret; the `pg_cron`
  job's command text; `pg_net`'s request and response records) are the right ones: a secret inlined in the job command
  lands in `cron.job` and run logs, and `pg_net` keeps queued request headers in its queue table until sent.
- **Edge Function relay.** Accurate; the note correctly observes the Cron still holds a secret to reach the relay.
- **Signed short-lived token.** Accurate; it correctly says the signing key is the same custody question and that the
  gain is a bounded replay window. See A1-306-I2.

## 5. Non-binding recommendation (Info; the decision is for its own record)

My leaning, for A1's later proposal and not decided here: **Supabase Vault holding a per-environment secret, read at run
time by the `pg_cron` job and sent in a `pg_net` request header**, with these conditions: the job's command reads
`vault.decrypted_secrets` at execution, so the secret never appears in `cron.job.command` or `cron.job_run_details`; no
application role (`authenticated`, `anon`, `app_*`, `app_worker_login`) holds any grant on `vault`, `cron` or `net`
objects, shown by a test; the route's response body carries nothing sensitive (it is stored in `net._http_response`);
rotation is two-step (the route briefly accepts current and next, each compared in constant time, then the old is
dropped), recorded as a narrow amendment to "a dedicated secret". Rationale: anyone who can read Vault already holds the
database owner's power, so the secret adds no new trust holder; a leak lets a caller only trigger a bounded,
lease-guarded dispatcher round, not read data; the Edge relay adds a hop and a second secret without reducing who can
read the first; a timestamp HMAC minted in SQL from the same Vault key is a reasonable later hardening against replay of
captured requests, not a different custody.
