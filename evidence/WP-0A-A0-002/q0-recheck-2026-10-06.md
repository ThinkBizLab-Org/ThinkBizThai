## §4 New finding at `58f70b8b`

### Q0-E9 (non-blocking, digest/`[11]` class; same regression as Q0-E8, not closed by this round; cheap fix advised) — a word whose ASCII tail spells a keyword

`stripNonCode` grows a word only over `/[\w$]/`. A non-ASCII identifier character, or a U+200D ZERO WIDTH JOINER
(ID_Continue), ends the word for the scanner but not for V8. So in `πin`, the scanner reads the word `in`. The
previous significant character is `π`, not `.` or `#`, so `wordIsMember` is false, and `in` is in
`KEYWORDS_BEFORE_REGEX`. The `/` after it opens a regex that blanks the code up to the next slash, and the import
between them is hidden.

It is the same regression Q0-E8 was. `cfabb292` refused these forms, and the keyword rule merged at `3545de1a`
opened them. This round closed the `of` and `#` doors but not this one. The records do not name it. They say the
regex starts after the words `return`, `typeof`, … `in`, and `πin` is not the word `in`. The test case
`a word that only starts like a keyword` (`returned / 2`) pins the leading edge of a word, not the trailing edge.

**Candidate fix, measured (not a fix of mine, and not committed):** in a copy of `pristine/`, changing the word

as U+00A0 after `return` would then read a following regex as division, so its body becomes code, which fails
closed. The choice is A0's.

**Grade.** It needs a digested file edited and a regenerated manifest, the same footprint as Q0-E6, Q0-E7 and
