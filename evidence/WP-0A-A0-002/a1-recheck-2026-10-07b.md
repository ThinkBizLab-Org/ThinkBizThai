## 4. New finding at this head

### N3 — Medium. The keyword-before-regex change reads a NAME as a keyword, and hides imports (regression)

The merge-forced change starts a regex after any word in `KEYWORDS_BEFORE_REGEX` unless the word is a member
(`lastSignificant === '.'`). Two names spell those words and are not keywords to V8, so V8 divides where the
scanner opens a regex and blanks everything up to the next `/`:

- `of` is a contextual keyword, not a reserved word: `const of = 4;` is legal in a module.
- A private name `#return`, `#typeof`, `#in` ... is legal; its `#` is not a `.`, so `this.#return` is not
  treated as a member.

| Line inserted (digests regenerated) | Guard at `8206b0cb` | Suite | Outside markers |
|---|---:|---:|---:|
| `const of = 4; const e4a = of / 1; import '../../e4-outside.mjs'; const e4b = 1 / 1;` | **0** | 0 | **1** |
| `const of = 4; const e4a = of / 1; await import('../../e4-outside.mjs'); const e4b = 1 / 1;` | **0** | 0 | **1** |
| `const of = 4; const e4a = of / 1; export * from '../../e4-outside.mjs'; const e4b = 1 / 1;` | **0** | 0 | **1** |
| `class E4 { #typeof = 4; m() { return this.#typeof / 1; } }; import '../../e4-outside.mjs'; const e4b = 1 / 1;` | **0** | 0 | **1** |
| `class E4 { #return = 4; m() { return this.#return / 1; } }; await import('../../e4-outside.mjs'); const e4b = 1 / 1;` | **0** | 0 | **1** |
| `const of = 4; const e4a = of / 1; const e4t = [...test]; const e4b = 1 / 1;` | **0** (the same `[...test]` alone is refused) | 1 | 0 |

**It is a regression.** `extractImports` from the `cfabb292` guard on the same four import lines returns
`["node:test","../../e4-outside.mjs"]` (the walk saw the escape and the guard refused it); from the `8206b0cb`
guard it returns `["node:test"]` with no refusal. The earlier keyword misread (regex read as division) put
regex text into code and failed closed; this one blanks code and fails **open**, which `[11]` does not say.
It also contradicts the record: `[11]` says the regex starts "never after a member name", and a private member
is one.

Not stop-the-line: every form needs a digested, protected test file edited (route (b) class), it exposes no
secret or tenant data, and the clean tree uses neither form (`git grep` finds no `of /` and no `#<keyword>`).

**Condition (before merge):** fix in code with a test, which costs nothing on today's tree — drop `of` from
`KEYWORDS_BEFORE_REGEX` (a regex after `of` returns to the recorded, fail-closed division misread of `[11]`),
and treat a word whose preceding significant character is `#` as a member like `.`; add the `of` and
`#keyword` cases above to the regex/division table and to the E4 refusal cases. If A0 chooses not to fix,
the minimum is to correct the guard comment and `[11]` to say a contextual keyword used as a name and a private
name spelled as a keyword are read as a regex start and hide what follows, and to list both in `[9]`'s
residuals. I prefer the fix: this is the only misread in the list that the PR itself introduced.
