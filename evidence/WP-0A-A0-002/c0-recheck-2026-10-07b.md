## 3. New finding at this head

### N1 (blocking, code or text): the merge's keyword rule reads `of` and `#return` as keywords, which re-opens a static route `a217f2a2` refused

In `3545de1a`, stripNonCode starts a regex after any word in `KEYWORDS_BEFORE_REGEX` unless the word is a member
(`wordIsMember = lastSignificant === '.'`). Two words in that position are not keywords:

- `of` is a keyword only inside `for (… of …)`. In a module it is an ordinary identifier, so `let of = 1;` is legal.
- A private name is a member, but its prefix is `#`, not `.`. `this.#return` is legal, because a private name may be
  any IdentifierName.

In both cases the slash after the word is division. stripNonCode now opens a regex there, and the regex runs to the
next `/`, blanking the code in between. An `import()` placed in that stretch is never walked.

| Probe (one line prepended to `test-kits/db/ws905-fixture.mjs`, `regenerate:manifest`, real guard) | Guard at `8206b0cb` | Payload ran | Guard at `a217f2a2` |
|---|---:|---|---:|
| N1 `let of = 1, __g = 1; const __q = of / 2 + import('<out>') / __g;` | **0** | yes | 92 |
| N2 `class __C { #return = 1; f() { return this.#return / 2 + import('<out>') / 1; } } new __C().f();` | **0** | yes | 92 |
| N7 the N1 form split across newlines (`of` + LF + `/ 2 + import('<out>') /` + LF + `1;`) | **0** | yes | 92 |
| Controls: `__o?.return / 2 + import(…) / 1`, `__o.await / 2 + …`, `return /import/;` then `import '<out>'`, `for (x of /a/.exec('a') ?? [])` then `import '<out>'` | 92, 92, 92, 92 | — | — |

Why this is blocking, when K8 and K9 are not:

- It is a **regression at this head**. N1, N2 and N7 are refused at `a217f2a2` and pass at `8206b0cb`. The merge
  resolution created them.
- The records state the opposite. `[11]`'s NARROWED text and closure note §4 say the rule applies "never after a
  member name", and that "A regex after `)` and nested templates remain OPEN". N2 is a member name, and neither
  form is one of the two named residuals.

Its severity is still the digest class: a digested file must be edited and digests regenerated, the same as K8 and K9.
That is why it is not stop-the-line (§6).

The suite does not pin the rule's edges (§4: dropping `of` from the set survives, M8).

The cheap fix, which I measured in the probe clone and then discarded:

- Drop `of` from `KEYWORDS_BEFORE_REGEX`. A regex after `for (x of` is then read as division again. That fails
  closed, as PR #203's `return /…import\.meta…/` did, because the regex body becomes code and any `import` in it is
  refused.
- Count a word after `#` as a member: `wordIsMember = lastSignificant === '.' || lastSignificant === '#'`.

With both changes and `regenerate:manifest`:

- the clean tree gives guard 0, and the floor suite passes 43/43;
- N1, N2 and N7 give 92;
- the controls still give 92.

Pin it with two cases in the existing `a comment, a string and a whitespace run …` test, so the count and the
name digest do not move: `const a = of / 2;` (division) and `const a = this.#return / 2;` (division). Then show
that a mutant reverting each change fails that test.

Narrowing the text instead is acceptable only if both `[11]` and the guard comment name "an identifier `of`, or a
private name spelled like a keyword, before a division" as residuals, and closure note §4's "never after a member
name" is corrected. I do not recommend it: the code change is two tokens and removes a regression.
