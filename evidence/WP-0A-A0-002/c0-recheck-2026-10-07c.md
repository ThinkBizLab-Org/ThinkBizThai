## 3. New finding at this head

### N3 (blocking, code or text): a word whose ASCII tail is a keyword still opens a regex when non-ASCII characters lead it

stripNonCode's word tracker treats only `[\w$]` as identifier characters. A module identifier may also contain
non-ASCII letters (`éreturn`, `ไทยin`). In those identifiers:

- the tracked word starts after the last non-ASCII character, so it reads `return` or `in`;
- `lastSignificant` is that non-ASCII character, not `.` or `#`, so `wordIsMember` is false;
- the slash after the identifier is division, but stripNonCode opens a regex there;
- that regex blanks the code up to the next `/`.

This is the N1 class: a word that is not a keyword is read as one.

| Probe (real guard) | `58f70b8b` | Payload ran | `a217f2a2` guard |
|---|---:|---|---:|
| U1 `const éreturn = 4, __g = 1; const __q = éreturn / 2 + import('<out>') / __g;` | **0** | yes | 92 (the import is seen) |
| U2 `const ไทยin = 4, __g = 1; const __q = ไทยin / 2 + import('<out>') / __g;` | **0** | yes | 92 (the import is seen) |

Why this is blocking, on the same terms as N1:

- It is a **regression** from `a217f2a2`, made by the keyword rule in `3545de1a`. At `a217f2a2` the slash after any
  word was division, and the walk saw the import.
- **The records claim narrower behaviour than the code has.** `[11]` says a regex starts "after return, typeof, case,
  in, …". The guard comment says only module-reserved words count. In fact the rule fires after any identifier whose
  ASCII tail spells one of those words. Neither `[11]` nor the guard comment names this form as a residual.

The severity is still the digest class: a digested file must be edited and digests regenerated, as with N1, K8
and K9. It is not stop-the-line (§5).

**Cheap fix, measured in the probe clone and then discarded.** In stripNonCode, count any non-ASCII character that
is not whitespace as a word character:

```js
if (/[\w$]/.test(source[i]) || (source[i] > '\x7f' && source[i].trim() !== '')) {
```

`trim()` strips exactly the JS WhiteSpace and LineTerminator set. So a non-ASCII space after `return` still ends the
word, and `return /x/` stays a regex. With this change and `regenerate:manifest`:

| Run | Result |
|---|---|
| clean tree | guard 0 |
| floor suite | 43/43 |
| U1, U2 | 92 |
| P1, P2, P6 | still 92 |

Pin it with one case in the same existing test, so neither the count nor the name digest moves:

```js
["const éreturn = 4; const q = éreturn / 2 + import('./x.mjs') / 1;", 'division', 'a non-ASCII identifier ending in a keyword']
```

Then show that reverting the change fails that test.

**Fallback.** Narrowing the text instead is acceptable only if both the guard comment and `[11]` name "an identifier
with non-ASCII characters whose ASCII tail is a keyword, before a division" as an OPEN residual that hides an import.
I do not recommend it. The code change is one condition, and it removes a regression.
