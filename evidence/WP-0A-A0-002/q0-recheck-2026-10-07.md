## §4 New findings at `cfabb292`

### Q0-E5 (blocking) — `...import(…)`: a spread hides a literal dynamic import from the walk

`extractImports` finds `import`/`export` on the stripped text with `(?<![\w$.])(import|export)(?![\w$])`. The `.` in
that look-behind exists so a member named `import` (`x.import`) is not taken as the keyword. But a **spread** ends
in `.`, so `...import('…')` is skipped, and V8 evaluates it as a dynamic import. The fix round dropped the `.` from
the `require`/`createRequire` look-behind, but left it on `import`. The code comment and `open_blockers[9]` both say
a literal `import()` that escapes is refused, and this form is that case.

Measured with route (b)'s footprint, which is one line added and digests regenerated:

| Edit | Guard | Payload outside the copy |
|---|---:|---|
| `const q0spread = {...import('../../q0-outside.mjs')};` prepended to `test-kits/capability-profile.test.mjs` | **0** | ran (`node --test` on the suite exit 0, 1 marker) |
| the same, then the **whole `npm run check`** in a copy of the clone on the branch name (throwaway handoff refresh committed locally) | **0** at the guard step | ran: **`npm run check` exit 0, 713/713**, and 1 marker outside the copy |
| `const q0s = {...import('../../../q0-outside.mjs')};` prepended to `test-kits/db/ws905-fixture.mjs` (a route (a) module, now digested) | **0** | ran (`import()` of the fixture, 1 marker) |

An object spread of a promise copies nothing and throws nothing, so the suite stays green. An array spread
(`[...import(…)]`) throws "not iterable", but the module load has already started, and its payload ran as well (1 marker).

This is not a `stripNonCode` misread (`open_blockers[11]`). `stripNonCode` keeps `...import(` as code. The miss is
the keyword regex of the new walk. It is the same class as Q0-E1: a one-line static form, with the increment's own
footprint, that the walk claims to refuse.

**Condition Q0-C9:** make the look-behind reject a single member dot only, not a spread. For example, treat
`import` after `...` as the keyword, or refuse any `.import` that is not followed by `meta`. Add a test with
`{...import('<escape>')}`, and a mutant that restores the current look-behind must fail it.

### Q0-E6 (non-blocking; record correction, cheap fix advised) — a lone CR or U+2028 ends a `//` comment for V8, not for the walk

ECMAScript ends a single-line comment at any LineTerminator: LF, **CR**, U+2028 and U+2029. Both `stripNonCode` and
the new `literalAt` end it only at `\n`. Measured with route (b)'s footprint (one line, digests regenerated):

| Edit (`\r` is one CR byte) | Guard | Payload |
|---|---:|---|
| `// x\rimport '../../q0-outside.mjs';` | **0** | ran |
| `// x<U+2028>import '../../q0-outside.mjs';` | **0** | ran |
| `import // x\r'../../q0-outside.mjs'`, newline, `'node:fs';` (the walk reads `'node:fs'`, V8 loads the first) | **0** | ran |

The first two are an import that `stripNonCode` misreads as a comment. The fix round's records name that class as a
digest-class residual (`open_blockers[9]` and `[11]`, "an import stripNonCode misreads around"), so I grade it
non-blocking. The third reopens Q0-E1's decoy through `literalAt`'s own comment skip. The closure note says E1 is
fixed because the reader "steps over whitespace and comments and nothing else", and that statement is wrong for
this terminator. Each fix is a few characters in a guard already being edited: end a `//` comment at
`[\n\r  ]` in both scanners, or refuse any walked module that contains a lone CR, U+2028 or U+2029.
**Condition Q0-C10:** do one of these and test it, or name CR/LS/PS explicitly in `open_blockers[9]` and correct the
E1 row of the closure note.

### Q0-E7 (non-blocking; record correction) — a nested template ends the span before the interpolation is checked

The R0 R2 refusal checks each span that `stripNonCode` records as a template. `stripNonCode` ends a template at its
next backtick (`open_blockers[11]`). So in `` `${ `x` + import('…') }` `` the outer span is `` `${ `` and the second
span `` ` + import('…') }` `` has no `${`. Neither span is refused. Measured with
`` const q0n = `${ `x` + typeof await import('../../q0-outside.mjs') }`; ``: guard **0**, suite exit 0, payload ran.
This falls in the disclosed `[11]` class, so it does not block. But the guard comment says any `import` inside a
template literal's `${...}` "is refused outright", and the closure note says R0 R2 is fixed. A cheap closure is
to apply the loader-word check to every template span, not only to those that contain `${`.
**Condition Q0-C11:** close it, or qualify the claim in the comment and the closure note.
