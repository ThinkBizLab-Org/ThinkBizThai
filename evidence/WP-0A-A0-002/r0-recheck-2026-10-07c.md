### R15: a literal does not end an expression for stripNonCode

`stripNonCode` decides regex versus division from `lastSignificant`, and the comment at line 228 explains why
that is exact: only whitespace is appended for a comment, string or regex, so only the single-character
append can change the answer. That reasoning is the defect. A string, template or regex literal ends an
expression, but because it appends only whitespace, `lastSignificant` is still the character before the
literal (`=` here), and `regexCanFollow('=')` says a regex may start. The `/` after the literal then opens a
"regex" that runs to the next `/`, blanking whatever lies between:

```js
const r0s = 'a' / 2 + import('../../../r0-fin-outside/evil.mjs') / 1;
```

Guard 0, the payload ran; the same with a template, with a regex literal before the `/`, and with a static
`import` after `'a' / 2;`. It holds at `a217f2a2` and `8206b0cb` too, so it is not this round's regression, but
no role has named it and `[11]` does not list it. It is in the digest class (a digested file must be edited and
the manifest regenerated) and not stop-the-line. It is blocking for the same reason R7 and R11 were: the record
lists what stripNonCode misreads, and this misread hides an import and is missing.

Minimal fix, measured as a what-if and reverted: in the two places a string or template and a regex literal are
appended, also set `lastSignificant = '/'` (not in `regexCanFollow`'s list, so division follows). Clean tree 0,
floor suite 43/43, the four R15 shapes 92, the PR #203 shape still 0. Add one R15 case per literal kind to the
