## §4 New findings at `8206b0cb`

### Q0-E8 (non-blocking, digest/`[11]` class; a regression from `cfabb292`; cheap fix advised) — the new keyword rule reads a division as a regex after `of` and after a private name

The merge's `stripNonCode` change starts a regex after any word in `KEYWORDS_BEFORE_REGEX` "never after a member
name". Two kinds of word in that set can end an expression in an ES module:

- **`of` is not a reserved word.** `let of = 6; … of / 2` is a division, and the scanner reads the regex from that
  `/` up to the next `/` on the line.
- **A private name can be any IdentifierName,** keywords included (`#in`, `#return`, `#of`). `wordIsMember` looks
  only for `.`, and the character before the word is `#`.

Either way, whatever sits between the two slashes is blanked, so an `import()` there is hidden. Measured with
route (b)'s footprint (one line, digests regenerated):

| Edit | Guard at `cfabb292` | Guard at `8206b0cb` | Payload |
|---|---:|---:|---|
| `let of = 6; const q0of = of / 2; import('../../q0-outside.mjs'); const q0of2 = 1 / 1;` in `capability-profile.test.mjs` | 92 | **0** | ran; suite `node --test` pass 4, fail 0 |
| the same with `../../../`, in `test-kits/db/ws905-fixture.mjs` (a route (a) module, now digested) | n/m | **0** | ran |
| `class Q0P { static #in = 4; static run() { return Q0P.#in / 2 + import('../../q0-outside.mjs') && 1 / 1; } }` then `Q0P.run();` | 92 | **0** | ran |

So the forms that `cfabb292` refused now pass. It is still a `stripNonCode` misread of the kind `open_blockers[11]`
and `[9]` already place in the digest class ("a division after ++ read as a regex"). It needs a digested file
edited, so I grade it non-blocking, on the same terms as Q0-E6 and Q0-E7 last round. But `[11]` now says the regex
start applies "never after a member name (x.return / 2)", and a private member falsifies that. The fix is a few
characters. M8 and M9 show that dropping `of` from the set and counting `#` as a member marker each leave the 43
unit tests and the clean merged tree green. I did not measure `for (… of /re/ …)` after M8. Without `of` that
regex would be read as division again, the old `[11]` misread in the other direction, so the choice is A0's.
**Condition Q0-C12:** close both forms in code with a test each (e.g. `let of = 1; of / 2` and `#in / 2` must read
as division), or name `of` and private names explicitly in `open_blockers[11]` and correct "never after a member
name".
