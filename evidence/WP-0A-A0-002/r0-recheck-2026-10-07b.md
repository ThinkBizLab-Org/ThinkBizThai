### R11: `of` is an identifier, not a keyword

`KEYWORDS_BEFORE_REGEX` holds `of`. In a module, `of` is not reserved: `const of = 1` is legal, and `of / 2` is
a division. The new rule makes `stripNonCode` read the `/` after it as the start of a regex. The regex runs to
the next `/`, which is the first one inside the import's specifier, so the `import` keyword is blanked:

```js
const of = 1; const r0of = of / 2; import '../../../r0-rf-outside/evil.mjs'; // /
```

Prepended to `test-kits/db/ws905-fixture.mjs` with digests regenerated: guard **0**, the fixture imports
cleanly, the payload ran. At `a217f2a2`, before the merge's change, the same probe is **92**. So this head
accepts a static import that the fix commit refused. It is the `[11]` misread class and needs a digested
file edited, so its severity is the digest class, not stop-the-line. What makes it blocking is the same as
R7: the guard comment says "after a keyword it no longer is" read as division, and `[11]` lists the forms
still open as "a regex after `)` and nested templates". Neither names this, and this one is new in this PR.

The other words in the list are reserved in an ES module (`yield`, `await` and the true keywords), so `of`
is the only one that can also be a plain identifier there.

Minimal fix: drop `of` from `KEYWORDS_BEFORE_REGEX`. Measured as a what-if: N4 becomes 92, the clean tree stays
0, the floor suite stays 43/43, and the PR #203 shape `return /…import\.meta…/` is still read as a regex. The
cost is that `for (x of /re/…)` is read as division again, which no walked module has today (clean tree 0).
Add the N4 shape to `a comment, a string and a whitespace run do not change where a regex may begin`, and show
that a mutant putting `of` back fails it. No test pins `of` today: removing it leaves 43/43. Narrowing the
text instead (add "a regex after an identifier named `of`" to the comment and to `[11]`) is acceptable
only with the Owner's acceptance, because it records a regression this PR introduces as a residual.
