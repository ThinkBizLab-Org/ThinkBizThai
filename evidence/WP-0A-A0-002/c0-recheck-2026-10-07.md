## 3. New observations at this head

### R1 (non-blocking, records): stripNonCode misreads still hide a static import, and line terminators are a new instance

The walk finds the `import` keyword on stripNonCode's output. Wherever stripNonCode misclassifies code as a string,
comment or regex, the import is blanked and never walked. The records already place "an import stripNonCode misreads
around" in the digest class (`open_blockers[9]`, `[11]`). I measured four instances, all route (b) shape: one line
prepended to `test-kits/db/ws905-fixture.mjs` (digested, in the closure), `npm run regenerate:manifest`, nothing else.

| Probe | Prepended line (outside path abbreviated) | Guard | Outside code ran on load |
|---|---|---:|---|
| T1 | `` const c = `${'`'}${await import('<out>')}`; `` | **0** | yes |
| T2 | `//c0` + bare CR (`\r`) + `import '<out>';` | **0** | yes |
| T3 | `//c0` + U+2028 + `import '<out>';` | **0** | yes |
| T4 | `if (1) /'/.test(''); import '<out>';` | **0** | yes |

- T1 is a variant of R0 R2. The template refusal checks only the spans stripNonCode reports. A backtick inside a nested
  string ends the span early (the `open_blockers[11]` nesting defect). The `import` then falls into what the scanner
  takes for a single-quoted string. So the guard comment's "any `import`/`require` inside a template literal's `${...}`
  is refused outright" holds only where stripNonCode reads the template correctly.
- T2/T3 are new, not named anywhere in the records. ECMAScript ends a `//` comment at CR, U+2028 and U+2029, but
  stripNonCode ends it only at `\n`. The same mismatch applies to string literals. A bare CR is easy to miss in a diff
  view, and the records name diff review as what catches the digest class.
- T4 is the regex-versus-division class `[11]` already records (here after `)`).

None needs anything beyond the edit-plus-regenerate the digest class already discloses, and none is a regression: each
was equally open at `5de8b856`. I do not ask for a parser. I ask for one of two things, either acceptable:

- (a) records only: name line terminators (CR, U+2028, U+2029) and the nested-quote template variant beside the
  stripNonCode residual in `open_blockers[9]`/`[11]`, and qualify the guard comment's template sentence with "where
  stripNonCode reads the template";
- (b) cheap code: refuse, with exit 92, any walked module containing a bare CR, U+2028 or U+2029. No file in today's
  closure is likely to need one, but that has to be measured. Then only T1 and T4 remain for the records.
