## 3. Findings at this head

### F1 — Medium. The walk accepts and digests a non-`.mjs`/`.js` module and then does not walk it: `.ts` and `.cjs` escape with the same edits the Author measured as refused for route (c)

`assertImportClosureContained` queues every contained, digested target, but on dequeue skips any file not
ending `.mjs`/`.js` (`// a JSON import is a leaf`). Node 24.20.0 loads `.ts`/`.mts`/`.cts` with type stripping by
default and loads `.cjs` through the CommonJS loader, and none of those files is scanned — so their imports,
their `require` and their `createRequire` are never seen. Measured, digests regenerated, the new file's key
added to the manifest and to `DIGESTED_FLOOR` (the same class of edit the Author's route (c) row made and
reported as exit 92):

| Mutation | Guard | Suite | Outside markers |
|---|---:|---:|---:|
| `test-kits/e4p.ts` = `import '<outside>/payload.mjs';`, `import './e4p.ts';` in `capability-profile.test.mjs` | **0** | 0 | **1** |
| `test-kits/e4p.cjs` = `require('<outside>/payload.cjs');`, `import './e4p.cjs';` in the same suite | **0** | 0 | **1** |

This falsifies the increment's sentence "the walk refuses every one that escapes" for a module the walk itself
accepted. **Fix (cheap):** refuse any closure target whose extension is not `.mjs`, `.js` (under the repo's
`type`) or `.json`, or walk `.ts`/`.mts`/`.cts`/`.cjs` too and refuse `require` there; add a test per extension.
Not stop-the-line: it requires editing protected files (the manifest, the floor, a digested suite).

### F2 — Medium (record). Route (b) is not closed in general: code that is not an `import` token reaches outside code with only a digest regenerated

The walk sees import syntax; it cannot see evaluation. Each of these, appended to the existing digested suite
`test-kits/capability-profile.test.mjs` with digests regenerated and **no other edit** (no floor, no contract),
left the guard at **0** and wrote **1** outside marker:

- `await new Function('s', 'return import(s)')('<outside>/payload.mjs');`
- `await (0, eval)("import('<outside>/payload.mjs')");` — the specifier is inside a string, which `stripNonCode` blanks;
- `const nm = await import('node:module'); nm['create' + 'Require'](import.meta.url)('<outside>/payload.cjs');` — the
  `createRequire` refusal is a token match, so a computed property name passes.

Together with the disclosed residuals (spawned processes, data files, `stripNonCode` misreads), this means the
increment **closes route (a)** and **raises routes (b) and (c)** to "an import literal is refused", but does not
make "running outside code needs an import the walk can see" true. That sentence appears in the code comment,
in `author-increment-2026-10-07.md` §2 and in `open_blockers[9]`. **Condition:** correct those three texts to say
routes (b)/(c) remain open through evaluation (`eval`, `Function`, computed property access to `createRequire`)
and process spawning, and stay inside the disclosed digest class (open_blockers[1]): each needs a digested file
edited and is caught only by diff review. A loader-hook design would catch the evaluated `import()` forms but
not `spawn`; I do not require it.
