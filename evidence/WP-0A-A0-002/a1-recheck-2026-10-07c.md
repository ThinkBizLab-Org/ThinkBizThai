Guard level, digests regenerated: `éreturn / 1; await import('../../e4-outside.mjs')` **92**; the `ไทยin` form,
dynamic and static, **92** / **92**. At `58f70b8b` these were guard 0 per C0 and Q0.

The rule is exact, not a heuristic: outside literals and comments V8 accepts only identifier characters,
whitespace (TAB, VT, FF, U+FEFF, any Zs) and line terminators as non-ASCII; `String.prototype.trim` strips exactly
the WhiteSpace and LineTerminator sets, so "non-ASCII and not trim-empty" is "identifier character" in any file
V8 will parse. U+2028/U+2029 are refused earlier anyway.

| `'a' /* c */ / 2 + import(...)` (comment between) | seen | HIDDEN |
| `'a'` newline `/ 2 + import(...)` | seen | HIDDEN |

Guard level, digests regenerated: my N4 string form `const e4s = 'a' / 1; await import('../../e4-outside.mjs'); ...`
**92** (it was 0 at `58f70b8b`), and the template and regex-literal forms **92** / **92**.

Why the sentinel is safe: in valid JavaScript nothing after a complete string, template or regex literal can
start a regex with `/` (ASI never inserts before `/`), so division is always right there; `'/'` is not in
`regexCanFollow`, and a comment between leaves it in place.
