## 3. Findings

### 3.1 R0-257-1 (Major): the new step runs `scripts.check` before the workflow's guard can check it

RFC-2026-007 put `node scripts/verify-test-coverage-floor.mjs` in the workflow as its own step **before** `npm run
check`, so that a `package.json` edited to neuter `check` "fails at a step that edit cannot reach". On `main` the
order is: classification steps, `npm ci --ignore-scripts` (runs no repository code), the guard, then `npm run
check`. The guard is therefore the first repository code that runs, and it pins `scripts.check` step by step.

This PR adds "Validate repository bootstrap with no node_modules" (`ci.yml:322-328`) **before** the clean install,
and so before the guard step (`ci.yml:336`). Whatever `scripts.check` says now runs first, with the working tree
writable, and the guard step afterwards reads the guard file from disk.

Demonstration, on an export of the head (`git archive 5ecd1371`, no `node_modules`), with `scripts.check` set to
`node -e "require('fs').writeFileSync('scripts/verify-test-coverage-floor.mjs','')"`:

| Order | Step | Exit |
|---|---|---|
| `main`'s order: the guard step first | `node scripts/verify-test-coverage-floor.mjs` | **81** ("check step … contains … which is not part of a command name or path") |
| this PR's order | `npm run check` (the new step) | 0 |
| | then `node scripts/verify-test-coverage-floor.mjs` (the guard step) | **0** |

The later `npm run check` step would also exit 0 (it runs the same string), and every later guard
(`verify-branch-scope.mjs`, the two application guards) reads files the first step could have rewritten. So a
`package.json` edit alone can again make CI green without the suite running, which is the class RFC-2026-007 and
the guard's exit 81 closed. The edit is still visible in the diff (`package.json` is governance, every role reads
it), which is what RFC-2026-007 says a workflow step is for going beyond.

`test-kits/app-stack.test.mjs` pins the new step's position as "after the classification steps" and before the
clean install; nothing pins it after the guard. RFC-2026-007 §E is about the classification steps, not the guard.

**Fix requested.** Run `node scripts/verify-test-coverage-floor.mjs` as a workflow step **before** "Validate
repository bootstrap with no node_modules" (it is dependency-free; it exits 0 on the head with no `node_modules`,
measured), keeping the existing guard step where it is or moving it; and pin in `app-stack.test.mjs` (or the guard's
own CI check) that the guard step precedes every step that runs `npm run check`, with a negative control. That is a
CI and test edit, so it is governance and re-read by every role.

**Security.** I refer this to A1 to grade. If A1 records it as a security finding of any grade, RFC-2026-025 §5 item
6 keeps A0 from pressing until it is closed.

### 3.3 R0-257-3 (Minor): `npm run check` fails after a local build

`scripts/scan-repository-secrets.mjs` ignores only `.git` and `node_modules` (`IGNORED_DIRECTORIES`, line 18). After
`npm run build --workspace apps/web`, the scan walks `apps/web/.next/` and reports 13 findings (PII-shaped strings in
`trace`, `.rscinfo` and a Next.js source map, a `secret-named-assignment` in Next's own source map, binary
Turbopack caches), and `npm run check` exits 70. With `.next` moved aside the scan exits 0. CI is green because its
build step runs after both `npm run check` steps; the manifest's `deterministic_commands.verify` lists the check
first too. But any developer, role run or `npm run verify` that builds and then checks gets a red check, and the
"WITH `node_modules`" half of RFC-2026-029 §8/6's spirit holds only on a tree that has not been built.
`test-kits/repository-json.test.mjs` was taught `.next` in this PR; the scanner was not.

Requested: either teach the scanner to skip `.next` (a guard edit on another package's digested file, with its own
negative control showing a secret in a tracked `apps/web` file still fails), or record it in the handoff's
`known_limitations` and the manifest's `open_blockers` with the package that owes it. I do not require the first in
this PR.

amendment's text say what the guard does, which is a wider decision the Owner has not made.

### 3.5 R0-257-5 (Info, owed): `src/**` is outside `npm run typecheck`

`tsconfig.json` includes `apps/**/*.ts`, `apps/**/*.tsx` and `vitest.config.ts`. When `src/modules/` lands, its files

forbidden to this package and does not exist, so the skeleton complies with RFC-2026-029 §2.1/1 today. Owed by the
first package that creates `src/`: add `src/**/*.ts(x)` to the project and to `app-stack.test.mjs`'s include
assertion. Adding it now is harmless (the `apps` inputs keep the project non-empty) and would make the rule hold
before anyone has to remember it.
