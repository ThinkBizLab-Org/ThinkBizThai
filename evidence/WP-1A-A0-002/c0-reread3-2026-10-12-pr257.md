## 5. New findings

### C0-257r4-1 (Low): "a PostCSS configuration other than `postcss.config.*`" is not refused wherever it stands

The new RFC paragraph ("Build configuration, and what the build included", RFC line 636–650) says: "a Babel
configuration, a PostCSS configuration other than `postcss.config.*`, a `vite.config.*` and a vitest workspace file are
refused wherever they stand." `scripts/app-boundaries.mjs` line 571 refuses `(^|\/)\.postcssrc(?:\.[a-z]+)?$` only,
and line 457 collects configuration files by the same names.

Next.js 16.3.8's Turbopack (the skeleton's `next build`) searches more names. The installed
`@next/swc-darwin-arm64` binary carries, besides `.postcssrc*` and `postcss.config.{js,mjs,cjs,ts,mts,cts,json}`, the
names `.config/postcssrc` and `.config/postcssrc.{json,yaml,yml,js,mjs,cjs,ts,mts,cts}` [measured with `strings`]. In
`.config/postcssrc.json` the file name is `postcssrc.json`, with no leading dot, so neither pattern matches it.

Measured on the head (each file removed after, `git status` clean):

| Tree change | `verify-app-boundaries.mjs` (text) | `--require-parser` |
|---|---|---|
| `apps/web/.config/postcssrc.json`: `{ "plugins": { "../../scripts/probe-c0-plugin.cjs": {} } }` | exit 0 | exit 0 |
| `apps/web/.config/postcssrc.mjs`: `export default { plugins: { "postcss-import": {} } };` | (not run) | exit 0 |
| control: the same JSON as `apps/web/.postcssrc.json` | (not run) | exit 1, refused as a PostCSS configuration |

The same reach shows in the allowlist's `configShapes.$comment` (it names `.postcssrc*`, which is accurate as far as it
goes) and the code comment at line 566 ("PostCSS reads `.postcssrc*` as readily as postcss.config.*"). The handoff's
"Babel, vite and .postcssrc configs refused" is accurate for the names it gives.

What I did not measure: I did not build (brief), so I do not know whether Turbopack prefers `.config/postcssrc*` over
`apps/web/postcss.config.mjs` in the same directory, or whether `scripts/verify-app-build-graph.mjs` would see what
such a file loads. A configuration that imports a repository module may show up in the build chunks' maps, as
`postcss.config.mjs` does in its clean control. A plugin named by a string is loaded when the build runs, and may not.
A1 grades the security side. I grade it Low because the RFC states a refusal that does not hold, in the class three
review rounds were about.

**Fix (A0's choice):** refuse `.config/postcssrc` and `.config/postcssrc.*` with the other refused files: add them to
`REFUSED_CONFIG_FILES` and to `RESOLUTION_CONFIG`'s collection, and add a negative control in the CLI and the suite.
The guard already walks `apps/web/.config/` (it counted my `.mjs` probe as a ninth source file). Or narrow the RFC
sentence and the `$comment` to the names the guard refuses. Before saying "wherever they stand" again, check the
other tools' search lists the same way: Next's `find-config.js` for webpack mode, and Vite's `postcss-load-config`,
which vitest uses when it processes CSS.
