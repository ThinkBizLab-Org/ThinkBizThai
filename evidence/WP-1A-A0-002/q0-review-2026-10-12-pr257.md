## 6. Findings

- **Q0-257-1 (Medium, blocks `test_verified`): §8/1's parity test does not hold the "where it may be imported" column
  for two provider SDKs.** `whereMatchesImports` (`scripts/verify-app-dependencies.mjs`) treats every backticked token
  in a cell as an admitted path prefix, so `@sentry/nextjs`'s "the composition root of `apps/web` and `apps/worker`
  only" admits any glob under `apps/web/` or `apps/worker/`; and it admits the `adapters` term's glob for any cell whose
  text contains the word, so `pg`'s "`src/modules/platform-kernel/adapters/**` … only" admits every module's
  `adapters/**`. Either widening passes the guard, the parity test and every suite, and the boundary guard then admits
  `@sentry/nextjs` in a page (MOD-900) and `pg` outside the job store. RFC-2026-029 §8/1 and the manifest's first
  acceptance criterion say a test fails when the copy and the RFC disagree, the "where" column included. Wanted: the
  definitional phrase "the composition root of `apps/X`" admits only `compositionRoot` globs under `apps/X`, the
  `adapters` term fires only on the bare word outside backticks, and a negative control for each of the two widenings.
- **Q0-257-2 (Medium, blocks `test_verified`): the amendment's rows are not held against the copy.**
  `compareAllowlistWithRfc` checks only that each exception's licence id and `named` string occur somewhere in the
  amendment section. The copy's package patterns are never compared with the rows (LGPL widened to `.*` passes), and
  deleting a row passes because the "What was found" paragraph names the same strings. The amendment's "How it is
  held" says the copy is "held against this section's text by the same test"; measured, it is not. Wanted: parse the
  amendment's table (licence, package cell) and compare it with the copy's exceptions both ways, with negative
  controls for a widened pattern and a deleted row.
- **Q0-257-3 (Low): a static import after a JSX closing tag on the same line is not seen.** The guard's header and the
  handoff disclose the `</tag>` misread for `import()` and say static imports "sit at the top of a module, where this
  does not arise". An ES module may put an import declaration anywhere at top level; `…</main>); } import { Pool } from
  'pg';` on one line passes the guard (M29). Deliberate, not accidental, but the disclosure should say it, or the guard
  should refuse an `import`/`export` keyword it cannot read past a regex start.
- **Q0-257-4 (Low): §4.8's numbers live in an unpinned copy.** `releaseAgeDays` can be set to 0, and a
  `releaseAgeExceptions` entry is admitted when its `a1_record` names any file in the tree (`README.md` passes); no
  test fails. A test pinning `releaseAgeDays` to §4.8's "seven days" and requiring the record under
  `evidence/**/a1-*.md` would hold them.
- **Q0-257-5 (Low): the CI wiring test checks the named steps, not the absence of others.** A second step running plain
  `npm ci` (install scripts on) and `continue-on-error: true` on the release-age step both pass every test. `ci.yml` is
  digested and governance, so review sees either; a test that every `npm ci` carries `--ignore-scripts` and that no
  application step has `continue-on-error` would make it mechanical.
