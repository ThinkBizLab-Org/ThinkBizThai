The two sentences:

- RFC-2026-029, Amendment 2026-10-12, "ESLint deferred" second paragraph (line 627–628). It lists the rules the guard
  holds, ending "and any `any` type in application code". It then says: "The guard's rules need no dependency, and
  `npm run check` runs them with none."
- Disposition §3 (b) (line 84): "Its rules need no dependency and run in `npm run check` with none".

Other parts of the PR say the opposite, and they are right:

- `scripts/app-boundaries.mjs` line 45–46: "`any` IS SEEN BY THE PARSER ONLY … `npm run check` (the text reader) does
  not hold §2.1/3's `any`".
- The handoff: "the `any` rule is held only by the parsed run".
- The CLI's own text-reader output says the same.

Measured: the text reader passed every `any` variant in §4.

The RFC's next paragraph says an `any` type "cannot be told from other text without" a parser. So a careful reader
can reconcile the two. But the governing record should not need that.

It is Low because nothing is unguarded. CI's `application` job holds `any` on every head, and A0 presses only with it
green.

**Fix (text):** "The guard's rules other than `any` need no dependency, and `npm run check` runs them with none; the
`any` rule needs the parser and is held in CI only." Make the same change in disposition §3 (b). A new head is not
needed for this alone.
