## 2. Review of the contract change

**Choosing the value per field (C0 R-2 on PR #196).** This answers what I asked. The seven fields I
named as keys are exactly the seven non-id rows. None of the 22 is a `scheme:path` reference, so 256 is
correctly used nowhere. Each value is sourced to an existing catalog number and declared a DECLARED
INFERENCE. Each note also says the bound is not a control against pasted credential material. That is
the honest framing, and it keeps A1's residual open rather than implying it is closed.

**The `sli_tags` pattern rewrite** (`^[a-z0-9_.:-]{1,64}$` became `^[a-z0-9_.:-]+$` plus
`maxLength: 64`). The accept set is identical: the character class is ASCII, so code-point length equals
quantifier length. I measured the edges: an empty string is still rejected (by the pattern), and 64
characters are accepted while 65 are rejected. The reason given is correct. With a `{1,64}` quantifier
and a `maxLength: 64` side by side, neither can be killed by a fixture, because removing one leaves the
other enforcing the same limit. This is the only "rule text" change that is not a pure addition. It does
not change meaning, requiredness or state, so it needs no RFC.

**Cross-contract compatibility.** SEC `scope.capability_key` and OBS readiness `capability_key` use
`^[a-z][a-z0-9.]*$`, which is a subset of the `sli_tags` class. With all three at 64, a credential's or
a readiness capability can always be carried as an SLI tag, which is what the notes claim. See N-2 for the
producer side.

**Co-owner countersignature.** It is recorded as OWED, not claimed: A1 for the eight SEC values, and A6
for the four AUD values and the ten OBS values. The new `open_blockers` entry gates leaving Draft, not
this merge. That matches what I said in R-2 ("Not a condition on this PR"). The Author says it did not see
an A1 role run sign SEC. If the A1 run in this workflow signs SEC explicitly, that signature is A1's to
record, not mine.

**Package status.** The manifest moves from `integration_verified` back to `in_review`. That is correct
for a new rule-changing increment on a package whose previous increment was integrated. The Author moves
it only as far as `in_review`. `open_blockers[14]` is closed in place "AUTHOR SIDE ONLY", with its
original text kept.

**Paths outside writable paths.** All five are declared in `amends_without_owning`, and
`verify-branch-scope` accepts each one as explained. `branch-identity.test.mjs` is in WP-0A-CON-008's
