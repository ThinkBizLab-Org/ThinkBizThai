## 4. The handoff range move (measured)

The handoff on `main` cites `82fafb3f..08791396`. At this head it cites `92968774..3e649261`.

I measured A0's claim that `refresh:handoff` exits 91 on the old citation. I used a throwaway local clone in the
scratchpad, with the package's branch name created at `92968774` (the branch as it was cut), and `main`'s handoff
unchanged. The clone was deleted afterwards.

- `node scripts/refresh-author-handoff.mjs --check` exited **91**: "cites 0879139, which is on no path to this branch".
- `node scripts/refresh-author-handoff.mjs` exited **91**, with the same message, and wrote nothing.

The cause is in the script. At a merge commit whose parents are both on `main`, the comparison point is the first
parent, `82fafb3f`, and `08791396` is not an ancestor of it. So the script cannot repair the citation by itself, and a
hand-set start at the branch point is the only way forward.

At the head:
- the stored base `92968774` is the branch point;
- `check:handoff` exits 0;
- `a5ad2314` touches only the handoff.

The move restates the range. It changes no content.

## 5. Findings

None is blocking. Both are advisory, and neither needs this PR changed before the press.

- **Q0-241-A1 (advisory, tooling).** §4 shows that `refresh:handoff` cannot rewrite a citation once the cited head
  has reached `main` through the PR's own merge and a new branch is cut at that merge. Every records branch cut that
  way will need the same hand-set range.
  - That is a defect of `scripts/refresh-author-handoff.mjs`, not of this PR.
  - It belongs to the script's owner, as a later increment.
- **Q0-241-A2 (advisory, carried).** Q0-239-A2 and A3 (the stale RFC sentences) stay with the §8 increment, as the
  transcription §4 and the handoff `known_limitations` say. This PR rightly does not touch the RFC, whose digest is
  pinned.
