## 1. x-lifecycle against the code

The job code is unchanged between `f20b7319`, which `x-lifecycle.decided` cites, and this head
(`git diff f20b7319 HEAD -- src/modules/platform-kernel/` is empty). The schema diff only adds lines. The one new key
is the top-level `x-lifecycle`. `additionalProperties` stays `false` and `required` is unchanged.

**Every decision function, enumerated.** `instantFromMilliseconds`, `instantOf`, `timestampOf` and `addSeconds` are
time helpers. `isLeaseHeld`, `isLeaseExpired`, `claimRefusal`, `isClaimable`, `isDeadLettered` and `holdsLease` are
predicates. `retryDelaySeconds`, `nextRetryAt` and `leaseExpiryFor` are computations. Five functions write a record:
`newJob`, `claim`, `heartbeat`, `complete` and `fail`, and `requestCancel` is the sixth. The application layer adds
dedupe and the over-cap refusal to enqueue (`fakes.ts`), the lease fence on each leased act, and the workspace-scoped
`requestCancel`. `worker.ts` calls only `claim`, `complete` and `fail`. It turns a timeout or a bad handler outcome into
`fail`, and it never calls `requestCancel` or `enqueue`.

**States (7). Every one is exact.** The order of `states` is the order of `claimRefusal`: `completed`, `cancelled`,
`leased`, `exhausted`, `not_due`, then null. `cancelling` is inserted before `cancelled`, as `cancel_requested_at` plus
`isLeaseHeld`. That split is consistent with the code, because `holdsLease` never reads `cancel_requested_at`.
`dead_lettered` at position 5 is exactly `isDeadLettered`: no result, no cancellation, attempt at or above the budget,
no held lease. `ready` is exactly `isClaimable`. `lease_held` is `isLeaseHeld`. No state is invented.
`app.jobs` has no CHECK that could make an ordered state unreachable or ambiguous; the lease pair is the only
cross-field CHECK.

**Transitions (14). Every one is exact, and none is missing.**

| Row | Checked against |
|---|---|
| enqueue, (none) → ready/waiting | `newJob`: attempt 0, progress 0, no optional field, `available_at` = the later of requested and now. A new job is never dead-lettered, because `max_attempts >= 1` (050 CHECK). The dedupe hit is in `writes`. |
| due, waiting → ready (clock) | `claimRefusal` stops returning `not_due`. A waiting job cannot reach dead_lettered, because only claim changes attempt. |
| claim, ready → leased | Refused unless `claimRefusal` is null; `attempt + 1`, owner, `now + timeout_seconds + leaseGraceSeconds`. |
| heartbeat, leased/cancelling → same | `holdsLease` admits exactly those two (completed holds no lease; dead_lettered and cancelled have none held). Expiry is the later of the two values; progress is not checked for increase. |
| complete, leased/cancelling → completed | `withoutLease` + `result_ref`. completed comes first in `states`, so a cancellation on the record does not change it. |
| fail ×3 | `attempt < max_attempts` → `available_at = nextRetryAt(now, attempt)`. The limits are whole positive seconds, so the delay is > 0 and the state is waiting, not ready. Otherwise `available_at` is kept → dead_lettered. From cancelling either branch derives cancelled. |
| lease expiry ×2 (clock) | leased → ready, because claim needed `available_at <= now` and nothing moves it while the job is leased; → dead_lettered at the budget; cancelling → cancelled. |
| cancel ×4 | `requestCancel` has no state guard: it writes on ready, waiting, dead_lettered (→ cancelled), leased (→ cancelling) and completed (written, state unchanged). It is a no-op once `cancel_requested_at` is set. |

`never` is accurate: each field is written only by the acts it names (enqueue excepted), and only cancel moves a
dead_lettered job (claim refuses `exhausted`). `actors` is accurate. The worker acts are fenced by `JobLease` and
`holdsLease`. The command path's two acts are `enqueue` (with a minted context) and the scoped `requestCancel`. Saying
the worker reaches the database only through the broker repeats RFC-2026-022 §5 items 5 and 6; it adds no rule.
`not_settled` names the D6 numbers in `job-limits.ts`, every-failure-retries (the `fail` comment), abort at timeout
only (`worker.ts` signal), non-monotonic progress, no replay, claim order and retention. Each item matches the code.
