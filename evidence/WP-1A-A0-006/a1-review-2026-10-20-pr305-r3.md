## 2. A1-305-3 (blocking): a unicode space before `#` makes a YAML content line look like a comment

Every reader decides "comment" with `/^\s*#/` (and "blank" with `.trim()`); JavaScript's `\s` and `trim` include
NBSP U+00A0, U+1680, U+2000-U+200A, U+202F, U+205F and U+3000. YAML's only white space is space and tab, so a line
`<spaces> # ...` is not a comment to YAML: deeper than a plain scalar it continues that scalar, and inside a
block scalar it is content. The reader drops it; NBSP renders as a space, so a diff shows a comment. Results (the
ASCII spelling of each is refused by the suite today):

| Insertion (application job) | Suite | PyYAML and Psych read |
|---|---|---|
| after `PGPASSWORD: postgres` in "Application tests": `             # ${{ secrets.PROD_DB_PASSWORD }}` | **21/21 pass** | `PGPASSWORD: "postgres  # ${{ secrets.PROD_DB_PASSWORD }}"` |
| after `DB_TEST_URL: ...` in "Database for the application tests": `             # ${{ secrets.PROD_DB_URL }}` | **21/21 pass** | `DB_TEST_URL` ends ` # ${{ secrets.PROD_DB_URL }}` |
| after `run: node scripts/verify-app-dependencies.mjs`: `           # \|\| echo NODE_OPTIONS=--require=/tmp/x.js >> "$GITHUB_ENV"` | **21/21 pass** | `run` gains the `$GITHUB_ENV` write (Q0-279r2-2's class) |
| in the toolchain step's `run: \|` body: `           # \|\| npm install left-pad` (` ` too) | **21/21 pass** | `run` gains a second, script-running install |
| after `          - 5432:5432`: `             # --privileged` | **21/21 pass** | port becomes `5432:5432  # --privileged` (the pin no longer holds) |

GitHub evaluates `${{ }}` anywhere in a string, so the first two put a secret on the two names `dbEnvProblems`
(new in this PR) exists to hold to the bootstrap values. Bash does not treat ` #` as a comment: `bash -e` on
`true` / ` # || echo HIDDEN-RAN` prints `HIDDEN-RAN` and exits 0 (bash's word delimiters are not
locale-dependent). On `main` (`0fc0e2f1`'s `ci.yml` and `app-stack.test.mjs`) the `$GITHUB_ENV` and `npm install`
insertions also pass 21/21, so the class predates this PR, as A1-305-2's did. Neither `main`'s nor the head's
`ci.yml` holds any of those characters (counted: 0).

Why blocking: it is A1-305-2's class (a line the reader takes for a comment that YAML reads), which `fe3e8f63`
says it closes as a class; and it defeats `dbEnvProblems` and the byte-for-byte service pin this PR adds. Why not
stop-the-line: nothing in `ci.yml` uses it, and planting it needs a merged governance change.

Fix shape (the author's choice): add U+00A0, U+1680, U+2000-U+200B, U+202F, U+205F, U+3000 (and the zero-width
U+200C, U+200D, U+2060) to `RAW_LINE_BREAKS`' refusal, so `ci.yml` holds no white space but space, `\t` and `\n`;
and/or make the comment test `/^[ \t]*#/` and the blank test `/^[ \t]*$/` in every reader. Negative controls: the
five insertions above, with NBSP and U+3000.
