## 3. A1-305-I3 (Info, backlog; also on `main`): a plain value ending ` :>` or ` :|` is read as a block-scalar header

`keyLines` and `applicationJobText` open a block scalar on `/:[ \t]*[|>][-+0-9]*[ \t]*$/` after removing a
trailing comment. A plain value such as `persist-credentials: false :>` matches, so the guard skips the deeper lines
after it as block-scalar body, where YAML reads `false :>` as a plain scalar and the deeper lines as its
continuation. Working insertion (21/21 at the head and at `main` `0fc0e2f1`; the same insertion without ` :>` is refused,
19/21):

```
          persist-credentials: false :>
            ${{ secrets.PROD_DB_URL }}
```

PyYAML and Psych read `persist-credentials: 'false :> ${{ secrets.PROD_DB_URL }}'`. Enumerated over every plain
value line of the application job: it passes only on `ref`, `persist-credentials`, `fetch-depth` (checkout's
`with:`), `EXPECTED_SHA`, `node-version`, `check-latest`; every other line (names, runs, `if:`, `BASE_SHA`, the two
DB envs, `needs`, `runs-on`, the service) is refused by the step-list, name, condition, env or service pins.
**Residual acceptable (fails closed in effect)**: the hidden lines can only continue one plain scalar (a key there is a
YAML error, and a `#` line ends the scalar), `applicationJobText` still reads them for the runner-env-write and
shell tokens, and each value it can reach either fails the job (`ref`, `EXPECTED_SHA`, `node-version`,
`check-latest` with a non-boolean) or is input to a SHA-pinned action that the extra text cannot change in meaning
(`persist-credentials` stays false, `fetch-depth` becomes 0). Not opened by this PR. Fix shape for the backlog:
open a block only when the indicator is the whole value (`/^[ \t]*(?:-[ \t]+)?[^:#]+:[ \t]+[|>][-+0-9]*[ \t]*$/`
on the key line) and refuse a plain value holding ` :` followed by `|` or `>`.
