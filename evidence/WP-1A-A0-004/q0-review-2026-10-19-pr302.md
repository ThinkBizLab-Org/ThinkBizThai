## 6. Findings (none blocks; all to backlog)

- **Q0-302-1 (Info, test gap).** The fake outbox's table-wide event_id uniqueness (050's
  `outbox_events_event_id_unique`) is exercised only within one workspace: narrowing it to per-workspace (MO19) leaves
  all tests green. Behaviour is correct today, and under MO19 a colliding event of another workspace is stored as a
  second row at its own position, so nothing is dropped or replaced and the ledger keys stay apart; but the fake's
  claim to model the constraint has no cross-workspace test. A test that commits event id X in workspace A, then
  appends X in B's unit and expects the refusal with A's entry unchanged, belongs with the adapter increment. MO16
  (append-time check removed, commit-time check kept) survives as near-equivalent: the duplicate is still refused and
  the whole unit rolled back, only later.
- **Q0-302-2 (Info, test gap).** `failureOf` accepts success only for `ok === true`; widening it to a truthy `ok`
  (MO31) survives, because no test returns `{ ok: 1 }` or `{ ok: 'yes' }`. The typed `EventHandler` cannot return one,
  so this is reachable only through an untyped handler; a one-line negative case would pin it.
- **Q0-302-3 (Info, test gap).** `freezeEnvelope` writes a fresh frozen `payload: {}`; keeping the delivered payload
  object instead (MO44) survives, because the check after the copy already refuses any key and no test asserts the
  stored or handed-over payload is frozen or a different object. A mutable empty payload on a stored entry could later
  gain a key and stop satisfying CTR-EVT-001; `Object.isFrozen(entry.envelope.payload)` and
  `not.toBe(delivered.payload)` in the existing frozen-copy tests would pin it.
