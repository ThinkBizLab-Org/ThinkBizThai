  these contracts is now WIDER than the wire, and nothing in the PR records it. Measured by reading at
  `bd8b56c`:
  - **NTF store.** `app.notifications` (051) has no length CHECK on `message_key`, `dedupe_key` or
    `deep_link_target_ref`. `dedupe_key` has only `notifications_dedupe_key_not_blank`, and no `ntf:`
    class.

      rejects (probe in §1).
    - 051's header and WP-0A-DB-00 `open_blockers[89]` still say the contract states no maximum. They
      say the DB will not invent one, because "a CHECK enforcing a bound the contract does not state
      would make the database stricter than the wire".
    - That condition is now removed. `[89]` was waiting for exactly this increment, and it is now
      answered on the contract side.
  - **USG store.** `app.usage_events` (061) mirrors CTR-USG-001's patterns "character for character". It
    has no length CHECK on `provider_key` and no CHECK for F-5, so an `estimated` row may carry
    `supersedes_usage_id`.
    - The id columns are `uuid`, so their 128 bounds hold trivially.

  **Why this is not stop-the-line.** RFC-2026-009 R-2 names the dangerous direction: a contract wider
  than the database, where the store rejects a value the contract accepts. This is the other direction.
  No contract-valid value is rejected. No migration changed, and nothing is lost or duplicated.

  **Why it still matters.** It is a contract/store divergence. The repo's convention is that the store
  mirrors the contract. The handoff's `migration_and_data_impact` reads "None", which is true of the
  diff and silent about the divergence.

  **What must be recorded, before the merge, in the manifest and the handoff (A0's edit, not mine):**
  - the divergence, field by field as above;

  - that a future `ntf:` CHECK on `app.notifications.dedupe_key` needs the 051 fixture keys replaced in
    the same change;
  - that WP-0A-DB-00 `[89]` is answered on the contract side.

  Whether the store follows the contract is DB-00's decision. It should follow A5's ratification
  (`[22]`), because a CHECK built on a bound A5 later changes would need a second forward fix.
