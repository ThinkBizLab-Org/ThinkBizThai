## 3. Findings

| ID | Grade | Finding |
|---|---|---|
| F-1 | **Medium, condition** | **CTR-NTF-001 `dedupe_key`: the new bound and the new class do not fit the composition the field itself declares as shipped.** The `x-pii-shape` states that the fixtures use `ntf:<source id>:<event>`, and the fixtures take the source id from `deep_link.target_ref`'s id. That fails in two ways. **(a) Length.** A key built from an id at its own bound (128, the same class value this increment gives `notification_id`) is `ntf:` + 128 + `:approved` = 141 characters, and it is rejected (measured). The `x-bound-note` sizes the key at the class bound because "this key has no stated composition to size against", but the annotation beside it states one. CTR-USG-001 ran exactly this composition check (320 ≤ 512). NTF did not run it. **(b) Character class.** The first segment admits `[A-Za-z0-9_-]` only. `target_ref` admits `.` inside a segment (`content:content.v2` is valid), but `ntf:content.v2:approved` is rejected (measured). So a valid contract value can make the same document's dedupe key unconstructible. Draft, no consumers, and the composition is A5's, so this is not stop-the-line. **Condition before merge:** either size the key to the shipped composition and let the first segment admit `.`, or declare in the `x-bound-note` / `untestable_by_schema` (2) that a key built from a long or dotted id does not fit, and that A5's ID-005 composition must be sized against 128 and this class. |
| F-2 | **Low, condition** (same edit as F-1) | **USG `allOf[0]`'s `x-rule` contradicts the tree.** It ends: "The invalid fixture that witnesses it is owed with the too-long fixtures, through WP-0A-CON-008's FIXTURE_SET." The fixture ships in this same commit and is in `FIXTURE_SET`. A contract annotation must not record as owed something it already carries.
