## 7. Findings

**Q-1 — Three new USG fixtures break declared cross-field rules beyond their named fault. Low; the same
class as my N4.** The subset cannot see either fault, so each file still gives exactly one error. A
consumer reading these fixtures as examples of "wrong in one way" would be misled.

The three fixtures and what each breaks besides its named fault:
- `invalid-attribution-workspace-id-too-long.json`: `attribution.workspace_id` (129) differs from
  `tenant_context.workspace_id` (the 36-character UUID). That breaks `untestable_by_schema` (5), A1's
  SC-1 tenant binding. Its `dedupe_key` still embeds the UUID, which also breaks (3).
- `invalid-attribution-business-profile-id-too-long.json`: `attribution.business_profile_id` (129)
  differs from `tenant_context.business_profile_id`, which is present. That breaks (5).
- `invalid-attribution-job-id-too-long.json`: `dedupe_key` embeds `job_synthetic_0001`, not the
  129-character `job_id`. That breaks (3).

Why it matters:
- PR #194 had just made every USG fixture agree with (5) and (3) (my `q0-recheck-2026-10-06.md` §4,
  "Fixtures now satisfy the declared rule"). This increment brings the disagreement back in three new
  files.
- It was avoidable. CTR-TEN-001's `workspace_id` and `business_profile_id` carry no upper bound (owed by
  CON-001), and the `dedupe_key` segment class admits 129 such characters. So each fixture could carry
  the same over-long value in both places and in the key. The new acceptance criterion says "fails for
  that bound alone", and that would then be true in the contract's sense as well as the validator's.

This does not block the merge. Hold it with `open_blockers[20]`, the N2/N4 class owed to CON-003 /
CON-008, or fix it in this increment; the fix touches no guard except the integrity of the fixture
bytes.

**Q-2 — The F-5 annotation says its witness is owed, but the witness ships. Low; record.** The `x-rule`
on CTR-USG-001 `allOf[0]` ends: "The invalid fixture that witnesses it is owed with the too-long
fixtures, through WP-0A-CON-008's FIXTURE_SET". In fact `invalid-estimated-carries-supersedes-usage-id.json`
is in the manifest, in `FIXTURE_SET` and in `outputs.files`.

The sentence was written before the fixture was added and was not updated. `ANNOTATION_DIGESTS` pins
it, so the correction moves that pin once more. This does not block the merge.

**Q-3 — "SITE_FLOOR is raised to the measured count" is not true for USG. Low; record.** The measured
USG count is 50 and the floor is 48. The `amends_without_owning.rationale` says "raised to the measured
count", and the Author record §7 repeats the numbers.

The gap of 2 is not new: on `main` `9b4a0ce` the count was 39 against a floor of 37 (CTR-AUD-001 and
CTR-SEC-001 carry similar slack). The increment carried it forward. It is harmless today, because
`CONSTRAINT_SURFACE` fails on any deleted site (P1, P5). But the sentence states a measurement that was
not made. Either set the floor to 50 or reword the sentence. This does not block the merge.

**Q-4 — The NTF `dedupe_key` bound does not fit the fixtures' own key shape at the id bound, and the
class admits a dotted name. Advisory, for A5 under `open_blockers[22]`.**

On the length:
- `x-pii-shape` says the shipped fixtures use `ntf:<source id>:<event>`.
- With a 128-character id (the id class bound this increment sets) and `:approved`, the key is 141
  characters, and it is rejected.
- The longest id that fits with `:approved` is 115 characters.
- For USG, A0 checked the composition against the bound (§3e). For NTF it did not, and the bound note
  says there is "no stated composition to size against".

On the class:
- It rejects `@`, `+`, whitespace and `/`.
- It admits `ntf:x:john.doe` and `ntf:john_doe`. Only "a bare run of digits" is recorded as a limit.
  The general producer obligation in (2) covers this, but the specific shape is not named.

Both questions belong to A5's composition decision (ID-005). Neither is a defect of this branch at
Draft.
