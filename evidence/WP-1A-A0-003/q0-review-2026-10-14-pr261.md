  first would mint a context with that actor id; the second would throw `TypeError` from the record check instead of
  answering `tenant.unauthenticated`). Owed: one test each.
- **Q0-261-2 (Low, test gap).** M30: A0's inference "the same key with another algorithm's hash is a conflict" is pinned
  only by a test whose hex digits also differ (`sha256:a…` against `blake3:c…`), so comparing only the hex part passes.
  Owed: the same hex under two algorithm names must give `conflict`.
- **Q0-261-3 (Low, test gap).** Two shared shape rules in `domain/json-shape.ts` survive both the unit tests and the
  fuzz: M26, the `Date.parse` instant check (no fixture or test holds a regex-shaped impossible instant such as
  `2026-13-01T10:00:00Z`, which `Date.parse` refuses); M27, required keys as OWN keys (JSON input cannot carry inherited
  keys, so neither fixtures nor fuzz reach it; the file's header claims it). Both agree with the validator today (§6);
  a regression would pass unseen. Owed: a unit test beside `json-shape.ts` for each (the catalog is out of scope).
- **Q0-261-4 (Low, manifest text).** The "PR-1 DEFERRALS" entry, item (a), says the classifier prints governance for
  `index.ts` "until the lane-walk fix of WP-0A-A0-004 (PR #260) is on main". PR #260 is on main (`6af75480`, this PR's
  base) and §7 measures governance for `index.ts` and for `run.ts` on this head all the same. The deferral is right; its
  stated end condition is not what the classifier does. The PR body's reason (RFC-2026-007 Amendment 2026-10-13 §B
  item 5) matches the measurement. For C0/R0: the entry should say the later PR is governance, not that the condition
  lapses with #260.
