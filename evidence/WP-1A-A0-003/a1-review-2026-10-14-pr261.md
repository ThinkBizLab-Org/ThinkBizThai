**Tenant isolation, by probe** (a temporary `zz-a1-probe/probe.test.ts` in my worktree, deleted before commit):

- **Uniform denial.** A cross-tenant workspace, a nonexistent one, a business of another workspace, a nonexistent
  business or page, a page of another business, a business outside a limited member's list, and a malformed id
  (`"ws_a\n"`, a full-width `"ws_ａ"`, `"ws_a\u0000"`) all give `tenant.scope.denied`, one frozen definition, the same
  bytes given the same minted correlation id. `TENANT_ID_PATTERN` is anchored without the `m` flag, so a trailing
  newline does not pass.
- **No existence oracle in the resolver's shape.** The only branches before the directory (`tenant.unauthenticated`,
  `tenant.selection.invalid`, the malformed-id denial) depend on the request alone, never on stored state. The
  principal is checked before the selection is read: an unauthenticated caller with any selection gets
  `tenant.unauthenticated` and the directory is not consulted (probe P10: 0 calls). The directory port returns a
  bare boolean, and only `=== true` admits, so no reason can travel back. Timing below the port is the adapter's
  (advisory N2).
- **Untrusted selection.** Any key other than the three scope keys (actor, locale, timezone, request/correlation/
  causation id) is refused; a client correlation id is never honoured (Q5). A JSON `"__proto__"` key is an own key and
  is refused. But see **A1-261-1**: inherited properties are read.
- **Forged contexts.** Only the module-private `WeakSet` decides; an `as` cast, a JSON round trip, a spread copy, a
  hand-written record, and the envelope's own `tenant_context` (probe P8) are all refused. The context and its actor
  are frozen; the envelope's record is a fresh frozen object without the brand symbol.
- **Failing dependencies.** A rejecting or **synchronously throwing** directory (probe P5) and a rejecting principal
  port give `platform.temporary` with `details: {}` and none of the failure's text. But see **A1-261-2**.
- **Idempotency.** A stored record with the same key in another workspace and a different hash gives `independent`
  (probe P9), never `conflict`: no cross-workspace oracle. Conflict is a constant definition; no stored content is
  copied into it.
- **Errors.** `stableError` has no cause parameter, always writes a fresh frozen `details: {}`, copies field errors
  field by field, and is re-checked against CTR-ERR-001; every `throw` in non-test code carries a constant message.
  `errorEnvelope` re-issues from the definition only, so an error with non-empty `details` is refused. See advisory
  N1 for errors made outside platform-kernel.

## 3. Findings

### A1-261-1 (Low): the resolver reads the untrusted selection's scope ids through the prototype chain

`application/tenant-context.ts` `readSelection` checks keys with `Object.keys` (own, enumerable) and presence with
`hasOwn`, but reads the values by destructuring, which follows the prototype chain; `scope` then takes
`business_profile_id`/`page_context_profile_id` whenever the read value is a string (`typeof business === 'string'`),
not when the key is the selection's own. Measured:

- P1: `Object.create({ workspace_id: 'ws_a' })` (no own keys) **resolves** to a context for `ws_a`.
- P2: with `Object.prototype.business_profile_id = 'biz_a'` set, the JSON-parsed selection `{"workspace_id":"ws_a"}`
  **resolves narrowed to `biz_a`**; the directory was asked for `{ws_a, biz_a}`, a scope the client never named.

The directory still decides with the server's actor, so this is no cross-tenant access. But the trusted context is
shaped by something other than the client's own keys, and under any prototype pollution elsewhere in the process every
request without a business is silently narrowed (writes attributed to a business the user did not choose, or a
uniform denial for everyone not in it). It also departs from `checkTenantContext`, which requires own keys, and from
the comment's "may name a workspace, a business and a page, and nothing else". **Fix:** read each id only when
`hasOwn` holds (and only from a data property, if A0 wishes), build `scope` from `hasBusiness`/`hasPage`, and add P1/P2
as tests.

### A1-261-2 (Low): the resolver propagates raw thrown values from its ports, contrary to the PR-1 DEFERRALS record

`resolveTenantContext` calls `ids.mint()` outside any `try` (`mintId`), and reads the principal's `kind`/`id`
(`isPrincipal`, then the actor copy) outside the `try` around `principal.current()`. Measured:

- P3: an id source that throws `new Error('zz-raw-idsource-secret')` makes the resolver reject with **that error,
  message intact**.
- P4: a principal whose `kind` getter throws `new Error('zz-raw-principal-secret')` makes it reject with **that error**.

The manifest's PR-1 DEFERRALS item (b) states that until the runner lands "the resolver throw[s] only constant-message
errors (… TypeError) for a programming fault, and nothing yet catches them". That is not what the code does: a port
adapter's own error, with its message and stack, leaves the resolver unchanged, and with the runner deferred nothing in
this package stands between it and whatever the composition layer does with an uncaught error. Nothing reaches a wire
in this PR (no composition, no adapter), hence Low; but the record is inaccurate on exactly the property acceptance
criterion 5 protects. **Fix (either):** catch around `ids.mint()` and the principal read and throw a constant
`TypeError` (or, for the principal read, refuse with `platform.temporary`/`tenant.unauthenticated` under the minted
correlation id); or correct the DEFERRALS sentence to say the resolver rethrows its ports' errors unchanged until the
runner exists, and make the runner PR's A1 reading confirm it catches them. The first is preferred; add P3/P4 as tests.

## 4. Advisories (not findings; none is open against this PR)

- **A1-261-N1 (for the runner PR and C0).** `errorEnvelope` accepts any CTR-ERR-001-valid error. CTR-ERR-001 leaves
  `code`, `message_key` and `field_errors[].field/code` unconstrained, so a caller in another module can still put a
  caught message in `code` or user input in `field` (probe P6: `"Error: zz-raw at /srv/app.ts:12"` and
  `"password=hunter2"` pass through). Acceptance criterion 5 holds for platform-kernel's own errors; for foreign
  errors it rests on callers. A stricter rule (only errors made by `stableError` from a `defineStableError` definition,
  held like the context's `WeakSet`) would be A0's inference beyond the contract; worth deciding with the runner.
- **A1-261-N2 (for the provider-bound increment).** The fake directory returns early at each failed link (workspace,
  membership, business, page). A real adapter that does the same with separate queries is a timing oracle for
  existence; it should answer membership and the Workspace → Business → Page relation in one query (or a reviewed
  database function) whose cost does not depend on which link fails.
- **A1-261-N3 (noted, for R0/Q0).** `successEnvelope` keeps the caller's `data` object by reference (not copied or
  frozen; CTR-API-001's x-leakage-boundary leaves it to per-command schemas), and a minted context can be passed to
  builders for any number of envelopes: binding one context to one request is the composition layer's job.
- **A1-259-N1 and N3 stay open as guard gaps** (`verify-branch-scope` ignores `forbidden_paths`; no guard refuses
  `node:`/`fetch` in `domain/`/`application/`). For this PR they are held by review: no `adapters/` file, and no
  non-test file uses I/O (§2). A1-259-N2 is closed for this PR by measurement (§2).
