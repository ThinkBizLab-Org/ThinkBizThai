### 2.1 The runner and FailureReportPort leak nothing (probed)

An untracked probe file (removed) drove `runCommand` through `index.ts`:

- The handler throws an `Error` with a marker message, a marker `cause` and `name`; a string; a symbol; a plain object
  with marker `message`/`stack`/`toString`/`toJSON`; a Proxy whose traps return or throw the marker. Every result is
  the `platform.internal` error envelope, and a deep walk of the result (own keys and values, six levels) and of
  every recorded report contains no marker.
- Replies that are not command replies: a throwing `kind` getter, a thenable whose `then` throws, a Proxy whose
  `getOwnPropertyDescriptor` throws, a structurally valid but unminted error carrying the marker in `code` and
  `message_key`, an accepted receipt with a marker extra key. All answered `platform.internal`; no marker.
- Ports: principal throwing, principal with a throwing `kind` getter, directory rejecting, id source throwing, id
  source minting a marker string outside the pattern. No marker in any result or report; the id-source cases are
  `uncorrelated` with `{ stage: 'resolve', answered: null, thrown: 'object' }` only.
- The report port throwing synchronously, returning a rejecting promise, or with a throwing `report` getter: the
  reply is unchanged and nothing escapes.

The report record is built by the runner from server-minted ids, a literal stage, a constant code and `typeof`; it is
frozen before the port sees it. `thrown` is `typeof`, which never runs a trap or getter.

### 2.2 Tenant isolation

- **Uniform denial** (probe): a member of `ws_a` naming `ws_b` (exists, not a member), naming `ws_nope` (does not
  exist), and naming a 103-character id give byte-identical results (`JSON.stringify` plus own keys), each a frozen
  plain object, with no report. A malformed id (`bad id!`) gives the same bytes without asking the directory; that
  shortcut depends only on the client's own input, not on existence. Mutation: making the not-admitted answer depend
  on the workspace fails 7 tests.
- **No existence leak in reports**: refusals that are answers (unauthenticated, denied, invalid) are not reported;
  only `platform.temporary` and caught throws are, and neither depends on whether a scope exists.
- **Untrusted client selection** (probe): a selection carrying `correlation_id` or `actor` is
  `tenant.selection.invalid`; under a polluted `Object.prototype.workspace_id`, `{}` is invalid, not `ws_a`.
- **Forged or JSON-rebuilt context refused** (probe): a JSON round trip, a spread, `Object.create(minted)`, a Proxy over
  a minted context and `tenantContextRecordOf(minted)` are each refused by `successEnvelope` with
  `UntrustedTenantContextError`. Forged errors (spread, JSON, Proxy, `Object.create`) are refused by `errorEnvelope`.
- **A1-261-N4 (own properties)**: closed in code; a principal `{}` under a polluted prototype is unauthenticated
  (probe and the PR's test). Mutating both reads back to `value.kind`/`value.id` fails the PR's test; mutating either

## 4. Advisories (not findings; nothing owed by this PR)

- **A1-265-N1 (extends A1-261-N3; composition increment).** `successEnvelope` holds the handler's `data` by
  reference, checked only as an object. Probe: `data` with an enumerable getter that throws the marker yields an
  `envelope` result, and `JSON.stringify` of it then throws the marker message, outside the runner's catch; mutating
  `data` after the handler returns changes the envelope. Not live (no wire exists). The composition increment must
  serialise inside a catch that answers `platform.internal`, or the runner should detach `data` inside its own try.
- **A1-265-N2 (residual of A1-261-N1).** `defineStableError` and `stableError` are exported, and nothing holds
  `defineStableError` to module-level constants: probe, inside a handler, `stableError(defineStableError({ code: m,
  messageKey: m, … }), id, [{ field: 'f', code: m }])` is accepted and `m` reaches the envelope. The manifest names the
  `field_errors` half as held by review; the runtime-definition half is not named. A later guard (definitions only as
  top-level `const` with literal fields) or review rule should name it.
- **A1-265-N3 (composition increment).** `resolveTenantContext` is exported, so any in-process caller with its own
  ports (an always-true directory) mints a context the builders accept: the brand proves the resolver made it, not
  which ports it used. The composition root should be the one place real ports are wired, and other modules should
  reach the resolver only through `runCommand` as composed there.
- **A1-265-N4 (test strength; Q0's to weigh).** The A1-261-N4 test makes `kind` and `id` inherited together, so
  reverting either read alone (`value.kind` or `value.id`) passes all 291 tests. The code is correct; one case per
  field would pin it.
- **A1-265-N5 (Q9).** Whichever increment adds the idempotency store or the first caller computing `payload_hash`
  should name Q9 as its gate and carry an A1 read: the actor binding is then enforced there, and a stored CTR-IDM-001
  `error` must be re-minted from its definition (as the manifest's "PR-2" entry says).
