`recommended_next_work_packages[0]`, say a branch creating `index.ts` prints governance "until the lane-walk fix of

the right reason (§B item 5). The conclusion — defer both files to a later pull request in the governance lane — stands.
Proposed: cite §B items 1 and 5 instead of #260's absence, and drop "after PR #260's lane fix lands" from the handoff's
next step. Note for R0: that later governance PR is not within `required_human_authorities[0]` (manifest, tsconfig
include, branch row only), so its press goes to the Owner unless a new direction covers it.

### C0-261-2 (Low, advisory): Q5 describes behaviour the resolver does not have

`open_blockers` Q5: "Until then the resolver accepts one only in the minted shape; always minting is the safer
reading." The resolver never accepts an inbound correlation id: `correlation_id` is not a selection key, so it is
refused as `tenant.selection.invalid` (`application/tenant-context.ts:41,68`; test `refuses a client-supplied
correlation_id`), and the id is always minted — which the code comment and PR body state. Proposed: Q5 says the
resolver refuses an inbound correlation id and always mints, pending CTR-OBS-001.

### C0-261-3 (Low, advisory to Q0): two checker rules the code gets right that no shipped test pins

Mutations that pass 184/184 of `src/modules`:
1. `domain/envelope.ts` KEYS without `'causation_id'`: the checker would then refuse a valid envelope carrying
   `causation_id` (stricter than CTR-API-001). No valid API fixture carries one, and API/ERR/IDM key and required
   lists are not pinned to their schemas as `TENANT_CONTEXT_KEYS` is.
2. `domain/json-shape.ts` `isDateTime` without `Date.parse`: the checker would accept `2026-13-45T10:00:00Z`, which
   the subset validator refuses.

Proposed: pin each checker's KEYS/REQUIRED to `properties`/`required` of its schema (and the nested ones), and add an
envelope with `causation_id` and an impossible-date record. Acceptance criterion 2, which is fixture-based, is met
without them; this is about keeping "accepts exactly" held after the next edit.
