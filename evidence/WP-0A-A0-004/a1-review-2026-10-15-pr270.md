## 6. Findings

### A1-270-1 (Low; against `main`'s workflow, not introduced by #270; not blocking): the audit that now runs first does not screen the packages that run first

`npm audit --omit=dev` (unchanged by this PR) leaves out every dev dependency. Measured: a local capture of the bulk
advisory request (`npm audit <flag> --registry=http://127.0.0.1:<port>/` at the head, lockfile only) sends **54**
package names with `--omit=dev` (`next` in; `typescript`, `vitest`, `tailwindcss` out) and **162** with `--include=dev`.
`typescript` (step 9 and 10), `vitest` (12) and `@tailwindcss/postcss`/`tailwindcss`/`postcss` (loaded by `next build`)
are devDependencies (`package.json`, `apps/web/package.json`), so the packages whose code runs first are screened only
by the release age (pull requests only, new lockfile entries only), not by the audit, malware advisories included. The
ordering this PR adds is right and helps for the production tree; the new `ci.yml` comment's "the two checks that would
report a compromised … package" holds for the audit only for production dependencies. Changing the audit's command is
outside item (1) (order only), so it is not asked of this PR. **Recommended follow-up (governance, owner of `ci.yml`):**
audit with dev dependencies included in the `application` job (or add a second `npm audit --include=dev
--audit-level=high` step in the same place), and pin it in `test-kits/app-stack.test.mjs`.

### A1-270-2 (Info; against `main`'s test coverage, not introduced by #270): a step condition on a package-code step is not refused

The new rule reads order, and the A1-257-4 test pins names and `run` lines; no test in `test-kits/` refuses a step-level
`if: always()` / `!cancelled()` / `success() || failure()` on a step after the checks (§3: 19/19 pass). Such a condition
would run package code after a failed audit or release age and so undo what the new order buys. Nothing on the head
does this, and any edit to `ci.yml` is a governance path read by four roles. **Recommended follow-up:** in the same
later item, refuse any `if:` in the `application` job except the release age's `if: github.event_name ==
'pull_request'` (the pattern `test-kits/branch-scope.test.mjs` already uses for the bootstrap job's steps).
