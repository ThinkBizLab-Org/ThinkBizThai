## 3. New findings

### A1-255r2-1 (Low): a planted import can hide a guard's dependency from the walk; the "never one named by a string" claim is not accurate

What a guard imports is read by `scanJs`/`jsRefs`, with `rawSpecs` as the backstop. The RFC-2026-007 Amendment
(2026-10-11 §D) and the handoff's `known_limitations` state that "a scanner misread can hide an import named by an
expression but not one named by a string" ("imports written as strings are still caught by a raw keyword scan"). That
does not hold. `rawSpecs` only takes a `'` or `"` that follows the keyword, whitespace and block comments. It misses a
backtick specifier, a parenthesized one, and one after a `//` comment. Behind a `scanJs` misread (a regex literal after
`)`, which the comment already discloses), all three are hidden. A symlinked module is a separate way in:
`laneOfRange` reads the link blob (the target path text), not the file node loads.

**Reproduced** as two steps: a planted base, as if a governance PR had merged, then a pull request that edits only
`src/lib/evil.mjs`. The planted guard was `scripts/verify-a1-probe.mjs`. Running `node` on it at the planted base
printed `LOADED src/lib/evil.mjs` in every case.

| Planted guard body | Lane of the edit to `src/lib/evil.mjs` |
|---|---|
| `import "../src/lib/evil.mjs";` (control) | governance |
| ``await import(`../src/lib/evil.mjs`);`` (no misread) | governance |
| `await import( // c` + newline + `"../src/lib/evil.mjs");` (no misread) | governance |
| ``if (true) /`/.test("x");`` + ``await import(`../src/lib/evil.mjs`);`` + ``// ` `` | **risk** |
| the same misread + `await import(("../src/lib/evil.mjs"));` | **risk** |
| the same misread + `await import( // c` + newline + `"../src/lib/evil.mjs");` | **risk** |
| `import "./lib/h.mjs";` with `scripts/lib/h.mjs` a symlink to `../../src/lib/evil.mjs` | **risk** |

The same `import(("..."))` without the misread prints governance: an import named by an expression, which fails
closed.

**Why Low and not blocking.** One pull request cannot do it. The plant is an edit to a guard, which is governance and
read by all four roles. The misread line, or a symlink under `scripts/`, is a conspicuous oddity in a guard diff. No
current file has a hidden import (§2). The coverage-floor guard's walk from the test files already refuses symlinks
and records the same scanner-misread class as open_blockers[11]. The edit to the hidden module is still tier H, and
A1 and Q0 read it. The step gates nothing.

**What would close it** (the Author's choice). Let `rawSpecs` also take a backtick specifier with no `${`, a
specifier after `(`, and one after a `//` comment (each only adds modules). Treat a mode-120000 or 160000 entry that
the walk reaches as a problem (governance), or follow the link. Change the amendment §D sentence and the handoff
limitation to say what the backstop covers. Alternatively, record this as an accepted residual with reasons, and
correct the sentence in the next pull request that touches the amendment.

All 29 test files are digested in `test-kits/integrity-manifest.json` (an `additive` governance path), and the
coverage floor refuses an undigested test. Any such pull request that passes CI therefore carries a manifest edit and
prints **governance**. The only effect left is that `additive-eligible: yes` can appear where the test's real subject
is `never`. No change is asked. A test with an opaque import could count as a `testSubject` problem, in line with the
closure.

### Considered and closed (no finding)

- **Time and memory.** Each scan is linear in practice (1 MiB adversarial inputs under 1 s; 4 MiB of `from from …`
  about 4 s, GC-bound). A larger head file the walk or `testSubject` must read can only reach `timeout 300` or an
  out-of-memory exit, and either prints not classified, which is governance. A `git` read over `maxBuffer` throws, so
  the module counts as unreadable, which is governance. The audit check's `changes.find` per path is quadratic only
  over audit paths, and its worst case is the same timeout.
- **Percent-encoded and `?`/`#` specifiers.** `./l%69b.mjs` resolves to no file at the head, which is a problem and so
  governance. Hiding a file this way needs a decoy file named with `%` planted by a governance PR, the same class as
  A1-255r2-1.
- **Bare specifiers** (`#imports`, a package self-reference) are skipped silently. `package.json` has no `imports` or
  `exports`, the repository declares no dependency, and adding either is a `never` path.
- **Forged output.** Lane reasons `JSON.stringify` every path, so no path can open a line at column 0. The step still
  needs exactly one `^lane: ` line, and the first line must be the tier line.
