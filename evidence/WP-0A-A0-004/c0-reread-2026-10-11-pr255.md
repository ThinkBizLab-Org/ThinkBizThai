## 5. New findings

### C0-255r-1 -- LOW, non-blocking: the additive-eligible mark is false, and its reason misstates §2.2, for the harness modules a guard test also imports

`governanceClosure` sets a module's kind from the additive roots first and then overwrites it with `guard` for every
module a `never` or `guard` root reaches. `test-kits/branch-scope.test.mjs` (a `never` root) imports
`tests/db/identity/run-isolation.mjs`, which imports `isolation-cases.mjs`; both are also in the harness's own closure
(`scripts/db/rls-smoke.mjs`). Measured at the head: a pull request changing only `tests/db/identity/isolation-cases.mjs`,
or that file with a migration, `scripts/db/run.mjs` and a fixture (the shape of a migration batch), prints
`lane: governance` with **no** `additive-eligible`, and the reason line says

> a module test-kits/branch-scope.test.mjs imports, read at the head: reached from a guard, which the additive rule does not cover

RFC-2026-034 §2.2's first additive bullet covers "pins, lint rules, proofs and self-tests for objects the pull request
itself adds, in `scripts/db/run.mjs`, the database test harness **or a module they import**", whoever else imports
that module; the second covers new test cases in any test file. So the sentence is wrong about the RFC, and the mark is
off for the rule's main use: the ten most recent merges to `main` that changed `isolation-cases.mjs` are all
WP-0A-DB-00 migration batches (batch-123 to batch-174) [measured `git log --first-parent --
tests/db/identity/isolation-cases.mjs`]. At `7c4d5764` the module was additive, and at batch-170's own merge
(`5558b266`, before `branch-scope.test.mjs` imported the harness) the head copy still prints that batch
additive-eligible [measured].

Why non-blocking: the lane is unchanged (governance either way; the mark never lowers or raises the lane), the side
is the fail-closed one (the readers lose a hint, nothing is admitted), and the handoff discloses it
(`known_limitations[1]`: "RFC-2026-034 §2.2 would let the runner's imports be additive. Stricter, so fail closed").
RFC-2026-007 §B states the rule ("`guard` for a module any `never` or `guard` root imports") but not this consequence.

**Asked (fix in this PR if another commit is made, else as a follow-up):** a module the database roots also reach
takes `additive` (bullet 1), or at the least the reason says that the harness also imports it and that whether bullet 1
covers the hunk is A1's and Q0's call; and one sentence in RFC-2026-007 §B naming the case.
