## 4. Q0-279r3-4: does GitHub read workflow keys case-insensitively?

Not measured on GitHub (no push). Established from source, read 2026-10-16:

- `actions/runner`, `src/Sdk/DTObjectTemplating/ObjectTemplating/Schema/MappingDefinition.cs`: the schema's
  `Properties` is `new Dictionary<String, PropertyValue>(StringComparer.Ordinal)`, a case-sensitive lookup.
- `actions/languageservices`, `workflow-parser/src/templates/schema/template-schema.ts`, `matchPropertyAndFilter`:
  a direct `definition.properties[propertyName]` lookup, no case folding; `template-reader.ts` reports an unmatched
  key as `Unexpected value '<key>'` (and detects duplicates by upper-casing, so `if` beside `If` is a duplicate).

So on both published implementations of the workflow template reader, `If:`, `Continue-On-Error:` and `IF:` are
unknown keys and make the workflow invalid: no run starts, the required `bootstrap` and `application` checks never
report, and the pull request cannot merge. That fails closed rather than skipping a step's failure. Residual: the
hosted service's parser is not the published source and was not exercised. Graded **Info**, closed as a risk on the
source evidence; A1 grades it for security.
