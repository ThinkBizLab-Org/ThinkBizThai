## 2. Findings

- **Q0-255-1 (blocking).** `laneOf` does not place the fixtures the database harness loads on the governance row.
  RFC-2026-034 §2.2 lists "the database test harness (… `db/foundation/seeds/**` and any fixture the harness loads)",
  and its additive bullet says "any other seed or fixture statement, an UPDATE or a DO block among them, is governance
  unless A1's confirmation names it". The harness loads `tests/db/identity/fixtures/*.sql`: `FIXTURE_SQL_FILES` in
  `tests/db/identity/run-isolation.mjs` (21 files), read by `scripts/db/rls-smoke.mjs` (CI's `make db-rls-smoke`) and
  `scripts/db/run.mjs`. No pattern matches them, the import closure follows only code modules, and they are not in the
  integrity manifest, so no other governance path is forced alongside an edit. Measured: an edit or an `UPDATE`
  appended to an existing fixture prints `tier: H, lane: risk` through the step itself (§1.4), and the historical
  commit `eb262b07` (two fixtures, a test and a README) prints `lane: risk` from the head's classifier. This is the
  lane printed lower than §2.2 gives, by a printer whose output RFC-2026-034 makes the judge; fix rounds that touch
  only a fixture are a recurring shape in this repository's history. The fix is small: a pattern for the fixtures
  the harness loads (for example `^tests/db/[^/]+/fixtures/`, kind `additive`, or the `FIXTURE_SQL_FILES` list read
  at the head as the closure reads modules), the RFC-007 §B sentence, and a test case for it. This needs Q0 again.
- **Q0-255-2 (minor, not blocking).** `laneOf` splits every path on `' -> '` and tests only the pieces, never the
  whole path. The diff is taken with `--no-renames`, so no real path carries a rename arrow, but a file name may
  contain `' -> '`, and then a `$`-anchored pattern can miss: `test-kits/x -> y.test.mjs` and `scripts/verify-a -> b.mjs`
  print `risk` [measured, §1.4]. In practice a new test file must also be digested in the integrity manifest (the runner
  refuses an undigested one), which is governance, and a new guard script runs only if something governance names it,
  so I found no green PR that lands lower through this; but the rule should test the whole path as well (or not split
  at all, since `--no-renames` holds). Fix with Q0-255-1.
- **Q0-255-3 (minor).** Mutation L12 survives: nothing pins that the governance patterns match case-insensitively,
  which the code comment and RFC-007 §B claim ("matched case-insensitively"). A test with one upper-case path would
  kill it.
- **Q0-255-4 (note).** `test-kits/<dir>/*.test.mjs` outside `db/` and `contracts/` (for example a new `test-kits/sub/`)
  prints `risk`. §2.2 names top-level `test-kits/*.test.mjs` as guards and `test-kits/db/**`, `test-kits/contracts/**` as
  not guards, and says "If it is unclear whether a path is a guard or runner, it is governance". A new directory there
  is unclear; the integrity-manifest requirement again forces governance today. C0 may rule.
- **Q0-255-5 (note, A1's to grade).** The audit lane trusts `github.event.pull_request.head.ref`. The repository is
  public [measured: `gh repo view`, `PUBLIC`], and a fork's branch may carry WP-0A-A0-001's branch name
  (`agent/root/WP-0A-A0-001-repository-bootstrap-2026-10-07` on main); a fork PR holding one audit directory would print
  `lane: audit`. The step gates nothing and the audit lane's readers still require four cherry-picked auditor files,
  so I do not grade it blocking; comparing `head.repo.full_name` with `github.repository` would close it.
