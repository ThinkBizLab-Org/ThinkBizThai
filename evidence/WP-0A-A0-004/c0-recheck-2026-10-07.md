The step exited 0. The log opens with `::stop-commands::<32 hex digits>`; the verdict line, the
classifier's reasons and all seven injected lines follow, indented; the log ends with `::<same token>::`
on its own line. Under `actions/runner`, while commands are stopped, only a line whose command equals the
token resumes them (`ActionCommandManager`), so the nested `::stop-commands::guess`, the `::guess::`
"resume", the V2 `::error`/`::add-mask::`/`::warning` lines and the legacy V1 `##[warning]` line are all
printed as text. The token is 128 bits from `/dev/urandom`, drawn per call, so a PR cannot write its
resume. The job summary's heading is `### Records-only classification (RFC-2026-025 §6.1): NOT RECORDS-ONLY`,
and the summary is a file, so a mask can no longer be registered in the step to rewrite it. The command
manager is created per step (`Handler.cs`: `hostContext.CreateService<IActionCommandManager>()`), so the
window cannot leak into a later step. (Runner source read with `gh api`; not run on the platform.)

## 4. New observations (Info only; none asks for a change before the press)

- **I1. A classifier output without a trailing newline glues the resume to its last line.** Measured
  with a stub base whose classifier ends with `process.stdout.write(...)` and no newline: the log's last
  line is `  x: no newline at end::<token>::`, so commands stay stopped for the rest of the step. That is
  the safe direction (nothing later in the step needs a command, and the stop ends with the step), and the
  real classifier prints only through `console.log`/`console.error`, which always end the line. A
  `printf '\n'` guard before the resume would make it exact; not asked.
- **I2. The runner model in the new test covers V2 `::` commands only.** The legacy `##[` form is also
  inert inside the window (probe above) but no test names it. Not asked; worth a line if the test is
  touched again.
- **I3. `check:handoff` is green on `61f14919` only because it compares the handoff against `HEAD^`**,
  by design ("a handoff cannot cite the commit that contains it"). With one more commit on top it lists
  `ci.yml`, RFC-2026-007, the contract lines, the suite and the manifest as drift. This is the known
  reason the handoff must be refreshed last and alone, and the brief says it is intentionally not yet
  refreshed; the throwaway refresh in §2 shows the guard then behaves.
- **I4. The closure note's §5 says 13 changed paths;** the committed head has 14 (the closure note
  itself is the fourteenth). Arithmetic only.
- **I5. The summary escapes HTML in the reason but not Markdown.** Only the non-`main` base-ref path
  puts outside text (`BASE_REF`) there, and a base branch is one the base repository already holds, not
  one a fork author names. No change asked.
