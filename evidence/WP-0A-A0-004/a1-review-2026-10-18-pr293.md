## 5. Findings

### A1-293-1 (Info, optional): the pin covers three redirections, not `GIT_CONFIG_*`

The strip is a class and §3 measures `GIT_CONFIG_*` refused, but the new test pins only `GIT_INDEX_FILE`, `GIT_DIR` +
`GIT_WORK_TREE` and `GIT_INDEX_FILE` + `GIT_OBJECT_DIRECTORY`. A future spawn site that bypasses `withoutCallerGit` is
still caught (any git child under `GIT_DIR` writes or fails), so this is coverage of a variant, not a gap. Optional: a
fourth redirection with `GIT_CONFIG_COUNT` → `core.hooksPath` and a hook that writes into the victim.

### A1-293-2 (Info, pre-existing, outside A1-292-2's class): non-`GIT_*` configuration still reaches `scratchRepo`'s git

`scratchRepo` passes `process.env` minus `GIT_*`, so `HOME`/`XDG_CONFIG_HOME` select the caller's global git config
(e.g. a `core.hooksPath` there runs in the scratch repositories); `runStep` passes `HOME` too. That is the user's own
configuration, not a caller-of-the-moment redirection, and `ratchets-bite`'s `CHILD_ENV` has the same scope. Reasoned,
not measured. Optional, with A1-292-2's "better still" shared helper: `GIT_CONFIG_GLOBAL=/dev/null`,
`GIT_CONFIG_NOSYSTEM=1` set after the strip.
