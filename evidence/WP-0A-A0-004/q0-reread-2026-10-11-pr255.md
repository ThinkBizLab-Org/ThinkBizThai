## 8. Findings

- **Q0-255R-1 (minor, not blocking).** Five survivors show properties the code and the RFC-2026-007 amendment claim
  that no test pins:
  - **N26:** the "linear" claim. With the memo off, `importSpecs` on `'/* from /* x */ '` repeated is quadratic:
    11 ms on the head and **34.7 s** for the mutant at 512,000 characters (1.7 s at 128,000) [measured: `n26-time.mjs`
    `3ade22d6…c5471f6b`, `n26-time.out` `98a6a561…249ee6c1`]. The linear-time test uses A1's shape and a long run, neither
    of which needs the memo. CI's `timeout 300` would still fail it closed.
  - **N27, N31:** the safety net RFC-2026-007 §B and the handoff rely on ("a scanner misread can hide an import named by
    an expression but not one named by a string"). No test has a misread hide a string import, so dropping the net, or
    its `require(` reading, passes.
  - **N33:** a double-quoted specifier in `importSpecs`, which the tier uses too; no test in either file has a `"`-quoted
    import.
  - **L9:** the head-branch comparison is case-sensitive in the code, but nothing pins it.

  None of these is a lane printed lower at this head: each survivor is a regression the suite would miss, not a defect
  present now. Five small tests would kill them (one quadratic-shaped input under the time bound; one module whose
  string import sits behind a misread regex, with a `require('…')` variant; one `"`-quoted import; one head ref differing
  only in case).
- **Q0-255R-2 (note).** RFC-2026-007 §B and the package rationale say that without `--lane` the classifier's output and
  exit codes are unchanged. The tier's `importSpecs` was rewritten. On real code that holds (§5: 60 PRs identical; 2,119
  of 2,121 files equal, the other two read more). On crafted text it does not: `import a from /* x */ y /* z */ './a.mjs';`
  gives `['./a.mjs']` from main's copy and `[]` from the head's, because main's lazy comment run stretched across code to a
  later `*/`. That text is not an import, so no real import is hidden and the tier is lowered only where main's copy
  raised on a false match. One sentence in §B ("the tier's import scan reads the same specifiers on valid code") would
  make the claim exact. WP-0A-DB-00's Integration Owner may want to note the rewrite in the acknowledgement owed.
- **Q0-255R-3 (note).** `testSubject` reads a test's direct imports at the head only. A deleted test whose subject was
  governance (`test-kits/db/rls-assertions.test.mjs`), a new test that reaches the classifier through a helper, and one
  that spawns the classifier by a path string each print `risk` on their own [measured: `e2e-extra.sh` `13443ee2…1b953c0c`,
  `e2e-extra.out` `07c9ee4b…fe347158`]. None can be CI-green alone: `node scripts/verify-test-coverage-floor.mjs` exits 91
  for the deletion and 87 for an undigested new test, so the integrity manifest must change. That makes the PR governance,
  but `additive-eligible: yes`, though a test that pins a classifier is not additive under §2.2. The mark is informational,
