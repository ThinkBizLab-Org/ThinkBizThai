## 3. Finding

### A1-287r2-1 (Low, blocking): a run body's write to a file later steps read reaches the env/PATH effect naming neither token, and the residual does not say so

Q0-279r2-2, which this PR closes, named this channel itself: "The same holds for `npm config set` writing a user
`.npmrc`" (`evidence/WP-0A-A0-004/q0-reread-2026-10-16-pr279.md`). N1 to N5 are plain text in a `run: |` body that the
reader reads and passes; they are not run-time assembly, not a glob, not `${{ }}`, and only N1 is arguably "what a
program a step runs does". The residual (test comment, PR body, the round-2 gov-a004g acceptance entry) opens with "the
reader sees the job's text" and lists what it does not see; a write in that text to a file other than the runner's
file-command files is not among them, so a reader of the residual would take the env/PATH class as closed. Same grade
as A1-287-2 (a residual that omits a channel to the same effect), and measured (N3) to undo an existing guard's pin.

Close either way (A1 re-reads either):
- **by the residual** (inside the item): add, in the same three places, that a `run:` body line writing a file a later
  step reads (a user or project `.npmrc`, by `npm config set` or a redirect; a program in a directory already on
  `PATH`; any other configuration file) reaches the same effects without naming either token, is not refused, and is
  held by the review of every `ci.yml` change; or
- **by class** (a third test, so an Owner-scope question for A0): every single-line `run:` of the application job is
  already pinned exactly by A1-257-4's step list; pinning the text of its two `run: |` bodies (the checkout check and
  the toolchain check) the same way would close every shell-body channel at once (writes, assembly, `set +e`).
