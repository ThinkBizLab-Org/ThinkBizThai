## 3. New finding

### A1-255r4-1 (Low): the residual-class statement is exhaustive, and modules named by a literal repository path still hide behind a misread

RFC-2026-007 Amendment §D now says: "A module can still hide from it **only if** a guard loads it by a path computed at
run time (not written as a literal), or by a loading mechanism that names no repository-relative path literally". The
classifier comment and the handoff limitation say the same ("One class can still hide a module"). Each probe below
names its module by a literal repository-relative path through plain `require` or `import`, and each prints risk
(`.cjs` guard unless marked; misread = A1's line `if (true) /`/.test("x");` … `// `):

| Probe | node | Pure form | CLI |
|---|---|---|---|
| N3: misread + `require("../src/lib/evil.txt")`; `evil.txt` holds `require("./evil2.cjs")`; edit `evil2.cjs` | loads both | **risk** | **risk** |
| N4: misread + `const p = "../src/lib/evil.txt"; require(p)`; edit `evil.txt` | loads | **risk** | **risk** |
| N5: misread + `const p = "../src/lib/evil"; require(p)` (an extensionless file, no `.js` sibling); edit `evil` | loads | **risk** | **risk** |
| N9: as N4 with `evil.md` | loads | **risk** | — |
| N7 (`.mjs`): misread + `const p = "./"×2100 + "../src/lib/evil.mjs"; await import(p)` (a 4 219-char literal) | loads | **risk** | **risk** |
| control: N4 with no misread | — | governance (an expression) | governance |
| control: misread + `require("../src/lib/evil.txt")`, edit `evil.txt` itself | — | governance (backstop) | — |

- **N3, N4, N5, N9: CommonJS runs any extension.** `require` of a file whose extension is not `.json`, `.node` or
  `.mjs` (`.txt`, `.md`, none) compiles it as CommonJS. The string rule drops such a string as data ("what a data file
  holds runs nothing"), and the backstop adds the file to the closure but `moduleReader` does not scan a non-`.js`
  file, so nothing it requires is followed. From code the same `require` is a problem (`WALK_READS`); the backstop
  flags only `CODE_NOT_READ` (`.ts`, `.tsx`, `.jsx`, `.node`, `.wasm`), not every non-`WALK_READS` target. Q0's R13 is
  different: there `cj.js` exists and resolves by extension.
- **N7: `STRING_MAX`.** A literal longer than 4096 characters is not a candidate, though node normalizes it to a short
  path. (The same literal inside `import(` is caught by the backstop; behind a variable it is not.)

None of these is "a path computed at run time" or "a mechanism that names no repository-relative path literally", so
the statement that makes the residual an accepted, stated class does not cover them, and they are not accepted
residuals.

**Why Low and not blocking.** Same plant as A1-255r2-1 and A1-255r3-1: a governance edit to a guard that holds a
conspicuous misread line and an odd `require`, read by all four roles; one pull request cannot do it; no current file
holds such a line; the edit to the hidden module is still tier H, read by A1 and Q0; the step gates nothing.

**What would close it** (the Author's choice):

1. Make the statement non-exhaustive and true: in §D, the classifier comment and the handoff, drop "only if" and say
   the walk is best effort and a planted guard can still hide a module from it (naming at least this CommonJS case and
   long literals as examples), the reader's check of a guard's module loading being the control. This records the
   whole residual as accepted without a further round of spellings. Or
2. Close the probes: treat a file a guard `require`s or names (string rule and backstop) whose extension node would
   run as CommonJS as code (scan it, or make it a problem as the code branch does), and drop or raise `STRING_MAX` for
   strings that normalize to a short path; pin N3, N5 and N7; and keep §D's wording only if it then holds.
