## 3. New findings

### C0-255r3-1 -- MEDIUM, blocking: the one-class residual statement does not hold; two literal-path loads still hide

**(a) A process a guard spawns.** The earlier §D said the lane "does not see what a module loads at run time
(`new Function`, `eval`, `node:vm`, a computed member such as `process.getBuiltinModule(name)`, **a process it
spawns**)". The corrected item drops "a process it spawns" and states the class instead. The string rule takes each
quoted span **whole**, so a path inside a longer string is not read, and a non-JavaScript program named by a whole
string is data ("adds nothing"). Measured in pure form (`laneOf`, tier H, a guard `scripts/verify-a1-probe.mjs` with
**no** misread, the pull request editing only the named file):

| Guard holds | Lane |
|---|---|
| `execSync('node src/lib/evil.mjs')` | **`risk`** |
| `spawnSync(process.execPath, ['--import=./src/lib/evil.mjs', '-e', '0'])` | **`risk`** |
| `spawnSync(process.execPath, ['-e','0'], { env: { NODE_OPTIONS: '--import ./src/lib/evil.mjs' } })` | **`risk`** |
| `spawnSync('bash', ['src/lib/evil.sh'])` (edit `src/lib/evil.sh`) | **`risk`** |
| `spawnSync('python3', ['src/lib/evil.py'])` (edit `src/lib/evil.py`) | **`risk`** |
| control: `spawnSync(process.execPath, ['src/lib/evil.mjs'])` | `governance` (the string rule) |

Through the CLI on a throwaway repository (base: the guard holding the `execSync` line; branch `pr` edits only
`src/lib/evil.mjs`): `node scripts/verify-c0-probe.mjs` at the base printed `LOADED src/lib/evil.mjs`, and the head's
classifier printed **`lane: risk`**, exit 0. Each path is written as a literal; none is computed; `execSync`,
`--import` and `bash` each name a repository-relative path literally. So the "only if" does not hold for them.

**(b) Resolution that is not node's.** §B: "An import resolves as node resolves it: the exact path; the path with
`.js`, `.mjs`, `.cjs`, `.json`, `.ts`, `.mts` or `.cts` added; a directory's `package.json` `main`, then its
`index.js`, `index.mjs` or `index.cjs`". The code (`resolveModule`) returns the **first** hit in that order. Node's
CommonJS `require` tries the exact path, then `.js`, `.json`, `.node`, then the directory; it never adds `.mjs`, `.cjs`
or `.ts`. Where a sibling file the walk tries earlier exists, the walk follows that file and never reaches the one node
loads. Measured in pure form (a guard imports `./helper.cjs`; `scripts/helper.cjs` holds `require('../src/x');`, no
misread):

| At the head | Node loads (measured, `require.resolve`) | The walk follows | Edit the loaded file: lane |
|---|---|---|---|
| `src/x.mjs` and `src/x/index.js` | `src/x/index.js` (and it ran: `LOADED src/x/index.js`) | `src/x.mjs` | **`risk`** |
| `src/x.cjs` and `src/x.json` | `src/x.json` | `src/x.cjs` | **`risk`** |
| control: `src/x/index.js` only | `src/x/index.js` | `src/x/index.js` | `governance` |

(Through `createRequire` in an `.mjs` guard the call is read as an expression and fails closed; the plain `require`
of a `.cjs` module is the open form.) The specifier is a literal; the mechanism is `require`. So this too is outside
the stated class, and "as node resolves it" is not accurate as written. The test comment above R13 to R16 also lists
"`.mjs` added" among "the other forms node resolves", which `require` does not do.

**Precondition, for A1's grading.** Each form needs a guard (or a module in a guard's closure) to hold the spawn or the
`require`, which is itself a governance edit; for (b), adding the shadowing sibling is also governance while the
`require` resolves to it. Unlike round two's directory link, I found no step that can arrive in a later non-governance
pull request. That is why §D's compensating sentence matters: "a reader of a governance pull request checks whether a
guard's module loading changed". A reader who trusts the "only if" is not told to look at spawned processes or at a
`require` that a sibling file can shadow.

**Why Medium for C0 and blocking:** the defect graded is text accuracy. This is the third version of the sentence that
tells readers what the lane cannot see. Each version has been contradicted by a measured probe, and this one also drops
a residual the earlier text stated correctly. RFC-2026-007 is the governance record readers rely on, and §D's reader
check depends on it. Whether any of this is open as a security finding is A1's ruling (RFC-2026-025 §5 item 6).

  processes it spawns changed". (A code change that reads paths inside strings and non-JavaScript programs is
