## 2. The step: safety (holds)

Compared line by line with the records-only step it is modelled on. The differences are: two base scripts copied in a
loop instead of one; any non-zero exit is "not classified" (stricter than the records-only step's exit-1 path); the
tier/lane parse and agreement check; `HEAD_REF` passed as one argv word from `env`. Measured:

- **Gates nothing.** No `id:`, no `continue-on-error`, no `GITHUB_OUTPUT`/`GITHUB_ENV`/`GITHUB_PATH`; its only
  `exit` is `exit 0`, reached through `report` on every branch (functions run in the step's shell, so `exit 0` ends
  the step). Every command that can fail under `bash -eo pipefail` is in an `if`, `|| true`, the left side of `||`,
  or between `set +e`/`set -e`. Pinned by the first new test in `test-kits/branch-scope.test.mjs`.
- **No expression injection.** `${{ }}` appears only in `env:`; `BASE_REF`, `BASE_SHA`, `HEAD_REF` are quoted shell
  variables. A git ref name cannot hold a space, newline or `:`, so neither `BASE_REF` in the reason nor `HEAD_REF`
  in a lane reason can open a workflow command; both are inside the stop-commands window anyway.
- **Runs the base's copies, before `npm ci`.** Both classifiers come from `git show ${BASE_SHA}:…` into a `mktemp -d`
  directory; node resolves the second from there, not from the checkout. Nothing of the pull request has run yet.
  `git diff` runs with `--no-ext-diff --text --no-renames` and `GIT_LITERAL_PATHSPECS`, so a head `.gitattributes`
  cannot run code or hide lines.
- **Fails closed on its own output.** First line must be `tier: <records|L|M|H> (`, exactly one `^lane: ` line, from
  the five-lane set, agreeing with the tier. **Reproduced** (scratch clone, step body cut out of `ci.yml`, run with
  `bash --noprofile --norc -eo pipefail`): on this PR the base classifier exits 2 with its usage line and the step
  prints `tier: H (not classified), lane: governance (not classified)`, exit 0. A path named
  `evidence/x\nlane: fast` on a base that carries `--lane` yields two `lane:` lines and prints governance (not
  classified); the forged line reaches the log only inside the `::stop-commands::` window.
- **Inert output.** Same token, escaping and 64 KiB cap as the records-only step; `</pre>` cannot close the summary
  block (`<` is escaped).
- **Output without `--lane` unchanged.** Base copy vs head copy, `copy` line set aside: byte-identical on

## 3. Findings

### A1-255-1 (Medium): `laneOf` is narrower than RFC-2026-034 §2.2, so a governance pull request prints `lane: risk`

The brief's question was whether a pull request can make the step print a lighter lane than it deserves. It can, by
path, without any trick. Each case below was **reproduced** as a one-commit pull request on base `7c4d5764` (the
first base that carries `--lane`), with the step body run as CI runs it. Each printed `tier: H, lane: risk`. Under
§2.2 each is governance, which needs all four roles on the final head; risk needs A1 and Q0, and A0 presses it.

1. **A fixture the harness loads.** §2.2 puts "`db/foundation/seeds/**` and any fixture the harness loads" on the
   governance row, and the additive bullet says "any other seed or fixture statement, an UPDATE or a DO block among
   them, is governance". `scripts/db/run.mjs` loads the 21 files under `tests/db/identity/fixtures/` that
   `tests/db/identity/run-isolation.mjs` names in `FIXTURE_SQL_FILES`. Appending `UPDATE x SET y=1;` to
   `tests/db/identity/fixtures/010-identity-fixture.sql` printed **risk**. `importClosure` follows imports only, and
   no pattern names the fixtures. RFC-2026-007's own Amendment 2026-10-06 (lines 170-184) already measured the
   harness surface, "the import graph of `scripts/db/run.mjs` … and every repository path those modules … name". It
   lists "the 21 fixture files in `tests/db/identity/fixtures/`". That list could serve as the reference.
2. **A module a guard other than the database runner imports.** `test-kits/contracts/json-schema-subset.mjs` is
   imported by two top-level guard tests, `test-kits/handoff-conformance.test.mjs` and
   `test-kits/protocol-schema-conformance.test.mjs`. Appending `export function validate(){return {valid:true,
   errors:[]};}` printed **risk**. That edit would make the handoff-conformance guard pass any handoff. §2.2
   continues "...and every module any of them imports" after the whole list of guards and runners. The rule's own
   tie-break is "If it is unclear whether a path is a guard or runner, it is governance". `GOVERNANCE_IMPORT_ROOTS` is
   only `run.mjs`, `rls-smoke.mjs` and `authz-proofs.mjs`. Today every other guard's local imports happen to be
   governance paths themselves. This helper is the exception, and any future `scripts/lib/*.mjs` a guard imports
   would be another.
3. **A test whose subject is a governance path.** §2.2 names "any test whose subject is a governance path".
   `test-kits/db/rls-assertions.test.mjs` imports and tests `db/foundation/test-helpers/rls-assertions.mjs`, which is
   on the harness row. A one-line edit printed **risk**. `tests/db/identity/identity-isolation.test.mjs` imports
   `scripts/db/run.mjs`. It is arguable because §2.2 also calls `tests/**` "not guards", and under the tie-break it
   should be governance too.

Why not stop-the-line: the step gates nothing and nothing is on `main` yet. A PR that the step wrongly puts on the risk
lane is still tier H, and A1 and Q0 read it, A1 being the role that would catch a neutered guard. RFC-2026-034 §2.2,
though, makes this classifier the judge of the lane ("never lowered by hand"). The RFC-2026-007 Amendment §B and the
step comment say the lane "follows RFC-2026-034 §2.2", and for these paths it does not.

**What would close it** (the Author's choice; I fix nothing). Compute the import closure from every governance code
path at the head (every path a `never`/`guard`/`additive` JS pattern matches, and the top-level guard tests), not
only the three database roots. Add the fixture files the harness loads: the path set `run-isolation.mjs` names, or
`tests/db/**/fixtures/**` wholesale, failing closed. Add tests that import a governance module (outside `tests/**`,
or including it under the tie-break) as governance. Pin each with a test, and make the Amendment §B state the closure
roots as built.

### A1-255-2 (Low): splitting on `' -> '` can only narrow, since the diff is `--no-renames`

`laneOf` matches `paths.flatMap((p) => p.split(' -> '))` and never the whole path. `classifyTierRange` runs
`git diff --raw -z --no-renames`, so no path holds an arrow from a rename. A real file whose name holds ` -> ` loses the
`^…$` anchors of every pattern. **Reproduced:** `test-kits/a -> b.test.mjs` (which `TEST_PATTERN`
`test-kits/**/*.test.mjs` would run) and `scripts/db/classify-x -> y.mjs` print **risk**. In practice a new test
file also needs `test-kits/integrity-manifest.json`, which is governance, so the first case is caught on its other
path. Fix: test the whole path as well as the pieces, or drop the split.

### A1-255-3 (Low): exponential backtracking in the import-specifier regexes, reachable through `importClosure`

`GAP = \s*(?:\/\*[\s\S]*?\*\/\s*)*` nests a lazy any-character run inside a star, so `from /**/ /**/ … x` (no
closing quote) backtracks exponentially (measured: 16 comments 2 ms, 20 → 8 ms, 22 → 24 ms, 24 → 92 ms; doubling per
comment). `importClosure` runs `RELATIVE_SPECS` (which reuse `GAP`) over every closure module at the head, so one
comment line `// from /**/ ×36 x` appended to `scripts/db/sql-lexer.mjs` made `classify-review-tier.mjs … --lane`
run past a 45 s alarm (killed, exit 142). The step has no timeout, so the job would hang to the 360-minute default,
and "exits 0 on every path" would not hold. It never prints a lighter lane, because it prints nothing, and such a PR is
governance anyway: a closure module changed. The same `GAP` already sits in `importSpecs` for L/M paths, which do not
exist yet. Fix: run the copy under `timeout` (exit 124 then prints not classified) and/or make the comment run
non-backtracking (`\/\*(?:[^*]|\*(?!\/))*\*\/`).

### A1-255-4 (Low): the audit lane and `additive-eligible` print wider than §2.2 lets them

- **Audit.** `AUDIT_PATH` accepts any status, mode and depth under one `evidence/audits/<date>/`. **Reproduced:** a
  symlink `evidence/audits/2026-10-12/link -> ../../../.github/workflows/ci.yml` plus one `.md`, with the audit
  branch as head ref, printed `tier: H, lane: audit`. §2.2/§2.3 give the lane to a PR that "holds only the round
  audit's files". Deleting or rewriting an earlier round's files, a symlink, or an executable are not those. A0's
  blob-equal reading (Amendment §D) would catch them; the printed lane should not invite it. Requiring status `A`, mode
  `100644`, and a `.md` leaf would match the RFC.
- **`additive-eligible`.** Every `test-kits/*.test.mjs` except `branch-scope`, `repository-json` and
  `test-coverage-floor` is `additive`. That includes tests whose subject is a guard's own behaviour, for example
  `ci-guard-behaviour.test.mjs` (it runs the `main()` of `verify-branch-identity`/`verify-branch-scope`),
  `secret-scan.test.mjs`, `toolchain-contract.test.mjs` and `handoff-conformance.test.mjs`. §2.2 says those are never
  additive. The flag never lowers the lane, and A1/Q0 confirm hunk by hunk anyway, but `additive-eligible: yes` on
  such a PR is a wrong hint.

### Information (no change asked)

- **I-1.** The fork `head.ref` case in §2 is closed only by the checkout assertion step. If the checkout ever moves to
  the merge commit or to `head.repo`, the audit branch check becomes spoofable. A one-line guard in the step (pass
  `--head-ref=` empty unless `head.repo.full_name == github.repository`) would make it self-standing.
- **I-2.** A bare `.github`, `.agents`, `docs` or `.claude` path (a file or symlink, no trailing slash) matches no
  pattern. For the directories that exist today, replacing one means deleting its files, which are governance. For
  agent-tool directories that do not exist (`.cursor`, `.codex`, …), a symlink of that name would print risk (tier H
  by mode).
