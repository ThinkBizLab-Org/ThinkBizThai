## 3. Findings at this head

Stop-the-line: **no**. Nothing here makes the text unsafe. R0-251-33 is a gap that either reading of which fails the
RFC's own stated effect or its own stated safeguard.

- **R0-251-33 (blocking, new). §2.2 does not place the guards' data files that every migration batch edits.**
  - **What is unplaced.** `db/foundation/lint/**` (the committed catalog snapshot; pinned grants, shapes, policy set
    and vocabulary checks; and the exemption registers `rls-exemption-register.json`,
    `read-allowlist-known-exceptions.json` and `index-coverage.json`'s exemptions) and `db/foundation/invariants/**`
    (checks the runner executes, and `superseded.json`, which retires them). The governance cell names scripts, "the
    database test harness … and every module any of them imports", "tool configuration", and says which test files are
    not guards; the additive list (lines 97–111) names pins "in `scripts/db/run.mjs`, the database test harness or a
    module they import". `run.mjs` reads these files; it does not import them. Neither list names them.
  - **Reading A: they are guards** (the pins and registers a guard decides on, or "tool configuration"; and line 87:
    "If it is unclear whether a path is a guard or runner, it is governance"). Then no line of the additive list admits
    an edit to them, and 12 of 12 batches edit `catalog-snapshot.json`, most with changed lines. Every migration batch
    is governance again, whatever A1 and Q0 confirm, and §1 lines 43–47 and §4 lines 194–198 misstate the effect, as
    R0-251-24 did.
  - **Reading B: they are not guards** ("anything unplaced" is risk lane, line 89). Then a new entry in
    `rls-exemption-register.json`, `read-allowlist-known-exceptions.json` or `index-coverage.json`'s exemptions, or a
    removed line in `pinned-grants.json`, takes the risk lane with no confirmation at all, while lines 101–102 make
    "an entry in any `*_EXEMPTIONS` list" in `run.mjs` governance and line 101 makes a `run.mjs` admission-list entry
    additive only when A1 names it (A1-251r5-1). The safeguard moves with the data: the RLS exemption register and the
    FK-support exemptions already live in these files (run.mjs lines 1995–2007, 3155). A1 still reads the risk lane, so
    this is not unsafe today, but it is not what §2.2 says it guards.
  - **Fix**, one bullet in a commit every role re-reads: name `db/foundation/lint/**` and
    `db/foundation/invariants/**` as guard data. An entry, pin or snapshot line for an object the pull request itself
    adds (including the snapshot rows its migrations create), and a superseding invariant that keeps the check it
    replaces, take the risk lane on the same confirmation, with A1 naming each; an entry in an exemption or
    known-exception register (`rls-exemption-register.json`, `read-allowlist-known-exceptions.json`, an
    `index-coverage.json` exemption) is governance, as `*_EXEMPTIONS` is; any other changed or removed line is
    governance. If the Owner should know the measured cost, §4 can add: "every batch also re-records the catalog
    snapshot". The guide does not change (passage (b) points to §2.2).

- **R0-251-34 (advisory, new). §4 line 198 cites Q-034-6 for both halves of a sentence it answers for one.** "A batch
  that also edits an RFC or CI … or renames a test, is governance (Q-034-6)". Q-034-6 (ii) excludes a batch that is
