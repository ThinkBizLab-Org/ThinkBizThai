**Why it fails.** Not because of the audit files: `scripts/refresh-author-handoff.mjs` counts `^evidence\//` as
`WRITTEN_AFTERWARDS`, so they are never drift. It fails because `driftBetween(cited, tipBefore)` diffs from the cited
head `376ff83` (an ancestor of `main`, merged with #252) to the branch tip, and the branch is recut from current
`main`, so every substantive path other packages merged since `376ff83` is counted as this branch's drift. A round
audit by definition follows other packages' merges (§2.3: the cumulative diff on `main` since the last audit), and the
audit PR may not touch the handoff (§2.2: "touching no other path"; §2.3: anything else takes that change's lane). So
whenever any non-WP-0A-A0-001 package has merged a substantive path since WP-0A-A0-001's handoff on `main` was last
refreshed, which is every real round, the audit-only head fails CI. **A0's reading is right:** the Audit lane of
§2.2 cannot pass CI as written while the handoff guard runs on WP-0A-A0-001's branch (C0-262-2).

**The fix I would want (governance PR, all four roles, the guard is a governance path):** make the handoff guard
measure the branch's own drift, not `main`'s: in `driftBetween`, when the cited head is an ancestor of
`merge-base(target, integration branch)`, diff from that merge-base instead of from the cited head, so only paths the
branch itself changed since it left `main` count; pin it in `test-kits/handoff-conformance.test.mjs` with a scenario
"a branch recut from main that adds only `evidence/**` is not drift, and one that adds a `src/**` path still is".
That keeps the audit PR evidence-only, as §2.2 intends, and keeps the guard failing for real drift. The alternative,
amending §2.2's Audit row to admit "WP-0A-A0-001's handoff refreshed last and alone", is worse: it puts A0-written
prose (this PR shows how it goes stale) into a lane whose only readers are the files' own blob checks.

(`classify-records-only` exits 1); §2.3 says an audit PR that changes anything else takes that change's lane; risk is
