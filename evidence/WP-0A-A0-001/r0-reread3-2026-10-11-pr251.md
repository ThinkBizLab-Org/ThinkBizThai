## 3. Findings at this head

Stop-the-line: **no**.

- **R0-251-24 (blocking, new; the guard half was latent at `90ee098e` and I did not see it). Adding a test, or a
  package's branch, edits a file the RFC names governance, so most risk-lane and fast-lane work would go to the Owner
  personally, which the RFC says it does not.**
  - **What the RFC says.** Line 82: governance includes `scripts/verify-*.mjs`, `scripts/*-contract.mjs` and "the
    top-level `test-kits/*.test.mjs` guard tests"; "Test cases a runner executes (`tests/**`, `test-kits/db/**`,
    `test-kits/contracts/**`) are not guards". Guide (b) puts "other scripts and test kits" in the risk lane. §1 (lines
    41–43) and §4 (lines 159–160) state the effect as "two readers (A1, Q0) instead of four" for tier H outside
    governance.
  - **What the repository does (measured, §1).** Adding a `test(...)` to any suite changes its name digest in
    `scripts/test-suite-contract.mjs`; a new test file needs three entries there and one in `DIGESTED_FLOOR` in
    `scripts/verify-test-coverage-floor.mjs`. Every new work package, and every `ownership.branch` move, edits the pinned
    table of `test-kits/branch-identity.test.mjs`. All three files are governance by line 82. Once §8 item 4 brings
    module tests under the runner, the same holds for every fast-lane M PR that adds a test, which RFC-2026-030 §4.1
    requires of M.
  - **Effect.** A pull request takes its highest path's lane. So a migration with its isolation tests, a contract
    increment with its catalog test, a new application package, and a records PR on a new dated branch would all be
    governance: every role, then the Owner pressing personally. Today they are tier H pressed by A0 under the standing
    delegation. The change is stricter, so it is not unsafe. But it contradicts the RFC's own "not guards" sentence,
    makes §1 and §4 misstate the effect the Owner is asked to approve, and leaves A0 either sending most PRs to the
    Owner or reading the guard list selectively.
  - **Fix**, one bullet in §2.2 beside the manifest bullet (lines 88–89), with A1's view on its safety. For example:
    "An edit to `scripts/test-suite-contract.mjs`'s per-file maps or to `DIGESTED_FLOOR` that only adds entries for,
    raises floors of, or records the new name digest of test files the pull request itself adds or changes, where its
    diff removes no `test(` line from them, follows those files' lane; a line of `test-kits/branch-identity.test.mjs`'s
    pinned table that matches an `ownership.branch` change the pull request itself makes follows that manifest's lane.
    Any other edit of those files, a lowered floor or a removed entry included, is governance." Q0 confirms the
