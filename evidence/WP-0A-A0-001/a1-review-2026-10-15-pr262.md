### A1-262-2 (Low; for a governance PR, not against this one): the audit lane has no green head, and the fix I would want

As §3 measured. The fix is a governance PR (it edits a guard and, if the text moves, RFC-2026-034), read by all four
roles. What I would want, in order of preference:

1. **A narrow exemption in the guard, keyed to the audit lane's own predicate.** In `the handoff for this branch
   describes this branch` (and `refresh-author-handoff.mjs --check`, which shares `driftBetween`), skip the drift
   assertion only when every path the branch changes against its merge-base with the base is an added or modified
   regular file under `evidence/audits/<date>/` **and** the branch is WP-0A-A0-001's `ownership.branch` at the base:
   the same test `laneOf` applies before printing `audit`, ideally the same function, so the two cannot disagree. With
   a negative control: the same branch adding one path outside `evidence/audits/<date>/` (and one adding the handoff)
   must still fail. This removes no check from any other branch.
2. Not preferred: measuring drift for **every** branch only over paths the branch itself changes since its merge-base.
   It is arguably more correct, but it loosens the guard for all packages, so it needs its own case.
3. **Not wanted:** widening the audit lane to admit a "mechanical" handoff refresh. This PR shows why: the refresh was
   mechanical in the fields the guard reads, and the prose that rode along unread was untrue (A1-262-1). A handoff carries
   free text, and the audit lane has no reader before merge besides CI.

Until that lands, each round's audit PR will need this PR's shape (risk lane, handoff last and alone, A1 and Q0 on the
final head), which is safe, only slower.
