## 4. New findings

### Blocking

- **Q0-251-17: the registries bullet does not reach the case it was written for, and §1 and §4 still state an effect the
  lanes do not give for migration and RLS work.** R0-251-24 (blocking at `7033114d`) was that adding a test edits a file
  the RFC names governance. The answer, line 90–94, lets a PR *add* an entry for a file it adds, and makes "removing or
  changing an existing entry" governance. But adding a test to an **existing** suite changes that suite's existing name
  digest, and usually its floors: measured by mutation (§2.4), the guard passes only after an existing entry of
  `scripts/test-suite-contract.mjs` is changed. On `main`, 12 of the last 12 DB-00 batches did exactly that, and all 12
  also edit `test-kits/db/foundation-contract.test.mjs`, which the rework newly names governance by example (§2.4).
  With `scripts/db/run.mjs` and its imports already governance, every one of those twelve migration and RLS batches
  would take the governance lane at this head: every role, as today. That is a narrowing and fails safe, but the Owner's
  option names migration/RLS as the work A1 and Q0 read ("คง A1+Q0 อ่านเฉพาะ PR ที่แตะ migration/RLS, auth, secret,
  payment"), and §1 (lines 42–43, "applies at once to tier H pull requests outside governance: two readers (A1, Q0)
  instead of four") and §4 (lines 167–168) tell the Owner that is the gain. As written the gain for that class is, as
  measured, none, and the rule invites A0 to read the governance list selectively to get it.
  **Fix, either:** (1) widen the bullet as R0-251-24 proposed: an edit of `scripts/test-suite-contract.mjs`'s per-file
  maps or `DIGESTED_FLOOR` that only adds entries for, **raises floors of, or records the new name digest of** test
  files the PR itself adds or changes, where its diff removes no `test(` line from them, follows those files' lane; and
  name governance by the classifier-pinning tests rather than the whole `foundation-contract.test.mjs` (or move those
  two tests to a top-level guard test); and say whether a DB batch that edits `run.mjs` case tables is governance; or
  (2) keep the strict reading and say it in §1 and §4 (migration and RLS batches that touch the harness, its test file
  or an existing registry entry take the governance lane) and put it to the Owner as Q-034-6. Either way A1 should
  weigh in on (1), and Q0 re-measures (b) if it changes.
