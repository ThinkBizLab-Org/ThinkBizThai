**Advisory.** I recommend fixing -1 and -2 before the §9 questions are put, because the Owner answers from that

- **C0-251r4-1. "Registries follow what they register" contradicts itself, and "follow those files' lane" can be read
  against the tier.** (line 90–94)
  - **Self-contradiction.** The first sentence admits a manifest regeneration that records the digests of files the PR
    "adds or changes", and a registry edit that adds "a test name or count" or "a row for a new or moved branch". The
    second sentence makes "removing or changing an existing entry" governance. A new digest for an already-digested
    file the PR changes, a test count raised by one, and a moved branch's pinned line are each a change to an existing
    entry. Read literally, every PR that edits a digested file is governance. That fails safe, but it is not what the
    bullet means.
  - **Tier.** All three registry files are unplaced paths, so the base's classifier prints H for any PR that touches
    them. "Follow those files' lane" could be read as letting a PR of L or M files plus a registry line take the fast
    lane. Lines 78–80 ("never lowered by hand") forbid that, so this is wording, not a hole. In practice the bullet
    only keeps such a PR out of governance; it takes the risk lane.
  - **Fix:** "… do not by themselves make the pull request governance; its lane follows the tier the classifier
    prints and its other paths. Removing an entry, or changing an entry for a file the pull request does not add or
    change, is governance." The bullet is not in §7, so no byte re-measure is needed.
- **C0-251r4-2. The audit lane's presser rests on a question that does not ask about it.**
