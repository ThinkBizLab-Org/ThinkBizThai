## 4. New findings

### Advisory

- **Q0-251-7: the handoff's prose is no longer true at this head.** Commit `5cb6d727` refreshed
  `handoffs/WP-0A-A0-001-author-handoff.json` "last and alone" but kept round-one text. `check:handoff` passes because
  it checks the cited range, not the prose. Four places still say "two CONTRIBUTING_AGENTS.md passages", where there are
  now four: `assumptions[1]`, the first `acceptance_results` criterion, `compatibility_impact`, and `rollback_or_forward_fix`.
  `rollback_or_forward_fix` also cites "RFC §10" for the rollback, which is now §11. `security_privacy_cost_impact` puts
  "CI and guards" in the risk lane, but §2.2 makes CI and the classifiers governance. `known_limitations[1]` says the
  lane is decided "by A0 from paths until the classifier prints it (RFC §8 item 2, WP-0A-A0-004)", but §2.2 says the
  tier is never lowered by hand and §8 item 2 names WP-0A-DB-00. The `tests` array records the round-one commit
  (`21af6654`, "all 8 changed paths"); nothing records a run on the rework commit. None of this changes what I measured.
  It matters for two reasons. The handoff is the record RFC-2026-002 item 2 asks the press to link. And carry clause
  (c) covers a later refresh only "with prose that stays true". Fix it in the §10 step-2 commit's handoff refresh.
- **Q0-251-8: the reversibility text admits sandboxed providers and hosted staging.** The old passage allowed only
  "reversible foundation that does not bind production schema or an external provider". The new passage (a) forbids
  "no live external provider account, credential or send", and §2.1 says "providers are faked or sandboxed". So a
  sandbox account and a sandbox credential with a third party are allowed before the G0 exit. The old wording did not
  allow them. The same holds for a hosted staging database, which is itself an external provider account. There is also
  a tension: §2.1 says "only replaces the list" of work types, but the provider qualifier changed too. The Owner's
  option does not mention providers, and §9 asks nothing about this. G0 tracker line 34 keeps "Stripe Thailand
  sandbox … `deferred after G0 by Product Owner decision 2026-10-05`". As written, a Stripe sandbox binding before G0
  would conflict with that row, although it would be tier H, risk lane. This is for C0 (fidelity) and A1 (safety). One
  remedy narrows (a) to "faked, or sandboxed only where an Owner decision already allows it". The other adds the
  question to §9.
- **Q0-251-9: §2.3 does not say how the audit files land.** A PR that adds `evidence/audits/<date>/*.md` is in scope
  for WP-0A-A0-001 (§2.2). It reads as tier H and as NOT records-only, because the records classifier accepts only
  `records-transcription-*`, `session-*` and `light-path-reading-*` directly under `evidence/<package>/`. By §2.2, every
  audit PR is therefore a risk-lane PR: A1 and Q0 must pass on a PR that holds their own audit files before it merges.
  §8 item 1 owes the first audit within seven days. The RFC should say which lane the audit PR takes, and who presses
  it. That is for R0 and C0.
- **Q0-251-10: in the fast lane, "green CI" does not run the PR's own module test.** RFC-2026-030's tier M requires
  "code inside exactly one module, `src/modules/<key>/**`, with a test in the same module in the diff". But
  `TEST_ROOTS` is `['test-kits', 'tests']` (`scripts/test-suite-contract.mjs`), and CI's test step is `npm run check`,
  which discovers `*.test.mjs` only under those two roots. A test at `src/modules/<key>/x.test.mjs` is therefore neither
  run by CI nor digested in the manifest. For a fast-lane PR, which merges on "green CI only", the test that makes it M
  never executes before the merge. `src/` does not exist yet, and today the fast lane is empty (§2.2), so nothing is
  exposed at this merge. The exposure opens with the Q-034-2 governance PR. §8 item 4 owes "CI runs application tests"
  but gives a weaker reason: the manifest cost. It does not order item 4 before item 5. Recommendation: state that
  modules are named in `M_ELIGIBLE_MODULES` (§8 item 5, Q-034-2) only after §8 item 4 has CI running the module
  tests. That is for A1 and C0.
- **Q0-251-11: §3's RFC-2026-002 row quotes text that RFC-2026-002 does not contain, and it names one clause of three.**
  The quoted "linked Author, independent Reviewer, independent Tester, Security/Privacy, Integration Owner evidence" is
  the old `CONTRIBUTING_AGENTS.md` bullet. RFC-2026-002 §Decision item 2 reads "Its handoff must link the head SHA, CI
  run, clean-diff result, Author self-check, independent Reviewer, independent Tester, required conditional
  reviewer(s), Integration Owner verdict, …". Item 1 ("Do not … merge an undrafted/unreviewed change") and item 3
  ("The Author cannot approve, test-verify, integrate, or authorize their own work. The Product Owner may perform the
  final manual merge …") are not named in "Amends" or §3. Yet the fast lane merges a change no role has read, and
  Q-034-1 has A0 press PRs it authored. R0-251-2 raised items 1 and 2. Whether item 3 must be named, and whether item 1
  needs naming once "unreviewed" means "no role read it", is for R0.

None of these is a test failure.

## 5. Fidelity [read; C0 owns the judgment]

Read against the option text in the disposition: "ยกเลิก gate 'ต้อง Frozen ก่อนเขียนโค้ด' · PR ทั่วไปผ่านด้วย CI
อัตโนมัติ + audit เป็นรอบ (ทุกสัปดาห์/ก่อนแต่ละ gate) · คง A1+Q0 อ่านเฉพาะ PR ที่แตะ migration/RLS, auth, secret,
payment".

- **Narrowings.** Several parts of the RFC are stricter than the option text:
  - The gate stays reversible (§2.1).
  - The fast lane is tier M and L only, and empty today (§2.2).
  - The risk lane covers every other tier-H PR, not only the four areas the option names (§2.2).
  - The audits add two extra triggers: first real data and first production deploy (§2.3).
  - A package moves past `in_review` only on R0's audit verdict (§2.3).
  - Governance PRs and records-only PRs stay unchanged (§2.2, §2.4).
- **Questions in §9.** Who presses the merge is Q-034-1. When modules are named, which opens the fast lane, is
  Q-034-2. The audit cadence is Q-034-3.
- **Neither.** Two things are neither a narrowing nor a §9 question. One is Q0-251-8, the sandboxed or hosted provider
  accounts. The other is §6, under which a running PR may take the lighter lane "if … the roles agree". That is a
  transition rule. I read it as within the option, but it is a hand decision about the lane next to §2.2's "never
  lowered by hand". It is for C0.
