   ownership change makes `cc-a5-loom.json` and `cc-a6-relay.json` this package's own paths; `cc-a6-relay.json`

   re-owning lowers no review. Adding the id to `knownRunIds` *tightens* the handoff approval guard. **But the
   A5 scope itself is wider than the disposition grants: F-1.**
2. **`can_access_external_secrets`.** `false`, schema `const: false`, validator exit 67 on mutation. `unavailable_tools`
   lists production/provider credentials and notification-provider accounts. Network and browser are declared `true`
   as harness facts, which is the honest direction (README: "must not overstate unavailable tools"); they are
   declarations, not grants, and the profile states an A5 assessment needs neither.
3. **Separation of duties with a same-lineage A5 (`[1]`).** RFC-2026-013 counts a signature from "a run **distinct from
   the author's**". `/claude/a5_loom` is a distinct run id spawned from the Author's run; `[1]` calls ratification
   after the fact "a weaker and different control". The Owner accepted that on a stated compensating control (Q4:
   §0 disclosure in every A5 file; A1, C0 and Q0 re-read). The profile records it as a validity condition ("A file of
   this run without that §0 disclosure is not an A5 signature"), does not claim more independence than exists, and
   gates signing on Q0's benchmark being on `main`. Residual risk: R-1.
4. **SC-2 (`[19]`) gating.** Preserved on `main`: `[19]` is untouched and binding. The profile's restatement keeps
   SC-2 at the Candidate move (Q3) but drops the other half of `[19]`'s text, "Before CTR-NTF-001 is ratified by A5":
   A-2.
5. **Press authority.** Q3 names the sequence (profile → A5 assessment → Draft→Candidate → RFC-2026-010 status line),
   which meets RFC-2026-025 §5 item 6 ("or must name its sequence explicitly"). The disposition makes each press
   conditional on C0, Q0, A1, R0 passing on the final head and CI green; the §5 item 6 conditions (head contains

6. **Secrets and personal data.** None. The disposition carries a session id prefix, timestamps and the Owner's chat

## 3. Findings

Stop-the-line: **no**.

### Blocking

- **F-1 (Medium, widened authority).** `limitations.role_scope` declares the run for "A5 (Loom) owner assessment and
  ratification of contracts A5 owns, **starting with** CTR-NTF-001"; the new `open_blockers` entry says "A5-owned
  contracts, starting with CTR-NTF-001", and the handoff assumption says the same. The Owner was asked one thing:
  "ให้ Claude run `/claude/a5_loom` รับบท A5 เพื่อประเมินและรับรอง CTR-NTF-001 ไหม?" (Q1), and Q4's acceptance of
  same-lineage ratification was asked in the frame of `[1]`, which is about CTR-NTF-001. Under RFC-2026-013 the
  profile *is* the instrument that makes a signature count, so "contracts A5 owns, starting with" lets this run sign
  any contract later assigned to A5 without a new Owner word, and without the benchmark Q2 scoped to this
  assessment. Today A5 owns only CTR-NTF-001 in `contract-catalog/shared-kernel/index.json`, so the exposure is
  prospective, but the text is the grant.
  **Fix on this PR:** limit `role_scope` (and the matching sentences in the new `open_blockers` entry and handoff) to
  CTR-NTF-001, and state that any other contract needs a new Product Owner disposition and an amendment of this
  profile before this run's signature on it counts.

### Advisory (fix in the same rework; I re-read them with F-1)

- **A-2 (Low, gating restated incompletely).** `role_scope` says the Draft→Candidate move is "conditional on this
  run's signature and on A1's confirmation that SC-2 is met". `[19]` quotes SC-2 as binding **before A5 ratifies or
  the contract leaves Draft**. Read alone, the profile tells the A5 run it may ratify first and SC-2 is checked later.
  Suggest: "This run's ratification counts only on a CTR-NTF-001 manifest that already states SC-2
  (`WP-0A-CON-006` `open_blockers[19]`); the Candidate move additionally needs A1's confirmation (disposition Q3)."
- **A-3 (Low, scope of the Frozen signature unstated).** RFC-2026-031 §3.2 item 2 has A5 sign CTR-NTF-001's
  **Frozen** text as owner. The disposition says "nothing here freezes CTR-NTF-001", and Q1's answer is summarised as
  "NTF then goes to Candidate". The profile's "ratification" does not say whether the Frozen-stage owner signature is
  in scope. Suggest stating that it is not granted by this disposition and needs the Owner's freeze disposition to
  name this run (§3.2 item 3 already requires the Owner to approve each freeze by name).
- **A-4 (Low, residual risk understated in the handoff).** `security_privacy_cost_impact` lists what the profile
  does *not* grant, but not the one authority it does grant: an owner signature on a contract the Author's lineage
  wrote. Name it there, with the Q4 compensating control.

### Observations (not findings)

- **O-1.** The capability values were declared by A0, not supplied by the run; the README asks for run-supplied values
  when A0 transcribes. The deviation is disclosed, has the `cc-a6-relay.json` precedent, and is gated ("a correction
  is made in this file before any signature of that run is cited"). Acceptable as written.
- **O-2.** The id `/claude/a5_loom` was used before, undeclared, by an authoring subagent writing as A0 (batch 090).
  The profile disclaims any signature for that work, retroactively or otherwise. Acceptable; readers of batch 090
  should keep reading it as Author work.
- **O-3.** Role authority in every profile is prose in `limitations`; no script reads `role_scope`. The control on
  F-1-type widening is this review and the readers of each A5 file, not a guard.
- **O-4.** The head does not contain current `main` (`5e444c53`). The sync is owed before the press (RFC-2026-025 §5
  item 6); from the diff stat it should be mechanical.

### Residual risk, carried forward to sequence item 2 (not a finding against this PR)

- **R-1.** Every reader on the NTF chain (the A5 run, and A1, C0, Q0, R0) is dispatched by A0, the author of
  CTR-NTF-001, and the Owner's Candidate approval (Q3) was given in advance and conditionally. So no
  lineage-external check remains between the A5 signature and Candidate except the conditions themselves. The
  specific mechanism of the "weaker and different control" is A0's prompt to the A5 run. When I read sequence item 2,
  I will expect the A5 file to reproduce verbatim the brief A0 gave the run, in addition to the §0 disclosure, and I
  will check A-2's ordering (SC-2 stated in the manifest before the ratification).
