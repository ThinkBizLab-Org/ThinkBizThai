## 3. Findings

### Blocking

**B-1. The profile declares a wider A5 scope than the Owner granted.**
- **What the Owner granted.** The disposition grants `/claude/a5_loom` the A5 role "to assess and ratify CTR-NTF-001".
  That is Q1's question text and the chosen option, which lists exactly blockers `[1][2][19][22]`.
- **What the PR declares.** `limitations.role_scope` declares "A5 (Loom) owner assessment and ratification of
  contracts A5 owns, **starting with** CTR-NTF-001". The manifest's appended rationale and `open_blockers[5]` say the
  same: "A5-owned contracts, starting with CTR-NTF-001". The handoff says "of A5-owned contracts, starting with
  CTR-NTF-001".
- **Why it matters.** Under RFC-2026-013, a signature counts for "roles a capability profile declares an agent run
  may hold". So this wording, once merged, is the authority. It is not a description of an authority granted
  elsewhere.
- **Where it would reach.** Today CTR-NTF-001 is the only catalog contract with `owner: "A5"`, but the reach is
  real:
  - the register gives A5 the UX message catalog (`sprint-0a-decision-register-contract-catalog-th.md:177`);
  - `WP-0A-DB-00` `open_blockers` still records batch 091's A5 review as owed. On 2026-09-28 the Owner chose (ค)
    there, **not** (ข);
  - under "starting with", this run could sign either of those without a new Owner answer.

  The disposition says "this question is new and outside the approved plan, so it was asked first". The profile
  should not quietly answer the next such question in advance.
- **Fix.** Make it a wording change in three files:
  - `role_scope`: "A5 (Loom) owner assessment and ratification of CTR-NTF-001 only (…). Any other A5-owned contract or
    owed A5 review needs its own Product Owner disposition, recorded in this file before this run signs it."
  - Apply the same narrowing to the two manifest sentences this PR appends. Both are new on this branch, so editing
    them does not break append-only against main.
  - Apply it to the handoff's assumption line.

  The fix must stay in those files. No other path needs to change.
