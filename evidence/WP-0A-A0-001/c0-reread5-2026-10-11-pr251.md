  condition as "once four roles pass and CI is green"; the Owner's option also carried "บันทึกคำคุณทุกครั้ง" (record
  his words each time). Optional to add.
- **C0-251r5-2 (rest of C0-251r4-1). "Follows the lane of the change it serves" against the tier and the fast lane.**
  - Every guard, runner and registry path in §2.2 is unplaced, so the base's classifier prints H for any PR that
    touches one, and lines 80–81 forbid lowering it by hand. In practice an additive guard edit keeps a PR out of
    governance and puts it in the risk lane, never the fast lane.
  - The gate itself says so: an additive edit needs A1's and Q0's written confirmation, which are the risk lane's two
    readers. A fast-lane PR has one Reviewer.
  - This is wording, not a hole: lines 80–81 and the fail-closed sentence decide it. **Fix:** "follows the lane its
    tier and its other paths give it (the risk lane, since every guard and registry path is tier H), not governance,
    when …". When §8 item 4 lets CI run module tests, the same fact means a fast-lane PR that must add a registry entry
    for a new test file prints H; that is §8 item 4's to solve, not this PR's.
- **C0-251r5-3. A new test that pins the classifier is both additive and governance.** Line 97 makes "new tests, in
  any test file, including `test-kits/db/foundation-contract.test.mjs`" additive. Line 86 names "the classifier's pins
  in `test-kits/db/foundation-contract.test.mjs`" as governance, and line 108–109 keeps "an edit … to the
  classifier's own pins" governance. A new test there that pins the classifier matches both. Line 109 ("If it is
  unclear … it is governance") resolves it safely. **Fix:** "new tests, in any test file (in
  `foundation-contract.test.mjs`, other than the classifier's pins)".
- **C0-251r5-4. "Removes or loosens nothing" should be read against what the manifest digests, not the manifest hunk
  alone.** Bullet 4 (lines 102–103) makes a regeneration additive when it "only records the digests of files the pull
  request adds or changes". If the PR weakens an existing test in a digested non-guard suite (`test-kits/contracts/**`,
  `test-kits/db/**`), that test edit is not a guard edit, and the manifest line that records it reads as additive. The
  integrity manifest exists to make exactly that change a reviewable line (`test-suite-contract.mjs` lines 43–53). It
  is not a hole: A1 and Q0 read the whole PR on the risk lane, not only the guard hunks, and the fourth revision had the
  same bullet. A1 judges the safety. **Fix (optional):** "a regeneration … that records the digests of files the pull
  request adds or changes, none of whose existing tests it removes or weakens".
- **C0-251r5-5. Stale prose in `open_blockers[7]`.** Its first sentence still says the Owner merges "after answering
  Q-034-1 to Q-034-5 himself". A0 updated that range in the third revision (from "Q-034-3"), but not in the fifth. The
