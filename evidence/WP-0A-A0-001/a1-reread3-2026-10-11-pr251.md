### Advisory

- **A1-251r3-1. Q-034-5 (a) checks each file but not the set, and nobody but the presser checks before the merge.**
  §2.3 makes C0's, Q0's and R0's audit files the verdicts that move a package past `in_review`, and A1's file a block
  only if it holds a finding; nothing requires A1's file to be present. Under (a), A0 assembles and presses the audit PR
  alone; blob-equality is self-checked, and the auditors' source commits are local, unpushed branches, so it is
  re-checkable only while they exist. If a file is missing (A1's, say), fast-lane work, which no A1 reads before merge,
  could reach `integration_verified` with no security reading at all. This matches RFC-2026-030's M and L today (no A1
  per PR), and option (b) closes it, which is why it is advisory. Recommend, if the Owner chooses (a): "a package moves
  only on an audit round in which all four auditors' files are on `main`, A1's included; each auditor confirms on `main`
  that its own file landed unaltered; the source commits are kept (or pushed) until the next audit."
- **A1-251r3-2. The guard list now says the tests that pin the classifiers are not guards.** Line 82 puts "either
  classifier" in governance but says "Test cases a runner executes (`tests/**`, `test-kits/db/**`,
  `test-kits/contracts/**`) are not guards". Measured: both classifiers' pinning tests, and the pin that CI runs the
  base's records-only classifier, live in `test-kits/db/foundation-contract.test.mjs`; the RLS isolation suite that

  and RLS tests in the risk lane is exactly what the Owner chose. Recommend one clause: "a test case that pins a
  governance path (the classifiers, the CI workflow, the integrity guard) is governance". The `Makefile` and
