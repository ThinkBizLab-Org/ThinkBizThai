## 4. Findings

**F1 — Medium, test gap, non-blocking.** A credential inside a long line is not pinned. Mutant X5 drops
every line over 1000 characters before matching and the suite stays 57/57. Every planted credential in
the new tests sits on its own line (`\n${value}\n` in the appended-copy test; head/middle/tail in the
offset test are each newline-delimited), so a line-length cut is invisible to them, and the files and
bytes the scanner reports are unchanged by it. Measured on this tree (`git ls-files`, 1620 files): 577
lines over 1000 characters in **126 files**, 5.6% of all characters, the longest 60 236; 422 of those
lines are in `.json` files, which is where manifests and handoffs carry one-line prose that an agent
could paste a value into. This is the M28 family at a smaller scale. Cheap remedy: in the appended-copy
test, splice the credential into the middle of each copied file's longest line (space-delimited) instead
of, or as well as, appending it on a new line; and add one 64 KiB single-line case to the offset test.
Owed before this package next changes the scanner.

**F2 — Low, test gap, non-blocking.** The property tests are bounded by the shapes the tree has today
plus 13 named future paths. The tree carries nine extensions (`.json`, `.md`, `.sql`, `.mjs`, `.gitkeep`,
`.yml`, `.txt`, `.node-version`, `.gitignore`), no CRLF file and no path deeper than five components, so
a skip keyed to any other extension (X2), to CRLF line endings (X9) or to depth (X10) survives. Today these
mutants read nothing less of this repository; they blind the scanner to files that do not exist yet.
Remedy where cheap: add a handful of common config extensions (`.yaml`, `.env`, `.toml`, `.sh`, `.py`,
`.pem`) and one CRLF file to `FUTURE_PATHS`, and one path deeper than ten. This is enumeration again,
which is acceptable here because the read-list test already covers whatever the tree grows into: the
day such a file is committed, the read-list and appended-copy tests cover it.

**F3 — Low, two unpinned claims in the L3 widenings.**
(a) The scanner comment says spaces are accepted "only in that grouping" (1-4-5-2-1). Free spacing (X8)
survives: the only spaced row in the false-positive table has a wrong check digit, so it does not tell
the two patterns apart. Remedy: a checksum-valid 13-digit run built at run time with a different spacing
(for example 4-4-5), required not to fire.
(b) The `(?<![A-Z])` lookbehind that keeps `PASS` from being the tail of `BYPASS` is held only by an
incidental line in `tests/db/identity/identity-isolation.test.mjs:4974` (a `KNOWN_BYPASS = …`
constant, owned by another package). The false-positive rows written for it do not test it:
`BYPASS_MODE=`, `AUTH_CONTEXT_HELPERS =` and `GIT_AUTHOR_NAME=` all have a further word after the
short word, so the "last word" anchor rejects them with or without the lookbehind. With that one line
renamed in a copy, removing the lookbehind leaves the suite 57/57. Remedy: a row whose name ends
exactly in `BYPASS` (`…_BYPASS=` with an 8+ character value) required not to fire.

**F4 — Records/CI, not a test finding; blocks the merge procedurally.** CI is red on `6cc6c93` at
`Verify branch scope` (exit 73) because `main` moved to `dd11c60` (PR #201, WP-0A-CON-003 records) after
the branch was cut, and the guard diffs against the PR base SHA. Against the merge-base the branch is
clean (exit 0, 9 declared paths). The Author disclosed this. RFC-2026-002 requires a green run on the
head, so a sync merge of `main` and a handoff refresh are needed. If that sync changes neither
`scripts/scan-repository-secrets.mjs` nor `test-kits/secret-scan.test.mjs` (digests in §1), this verdict
carries to the new head; if either digest changes, it does not.

**F5 — Low, records.** The Author priced the refused `:` widening at "7 lines in 4 files" at `b61735f`.
My measurement at this head, with the assignment pattern's `=` replaced by `[=:]` and placeholder values
excused, finds those seven (three in `.github/workflows/ci.yml`, three in two WP-0A-DB-00 evidence files,
one in `test-kits/db/foundation-contract.test.mjs`) **plus three more**: two quoting lines in my own
`test-verdict-q0.md` (lines 339 and 436) and one in `evidence/WP-0A-CON-004/security-disposition-handle-ownership-a1.md:125`.
The exact count depends on the variant of the widened pattern, and both counts support the refusal, so
the refusal stands; the recorded price is a lower bound and should say which pattern produced it.

**F6 — Low, environment.** `the size limit is enforced before the file is read` distinguishes stat-first
from read-first through a `chmod 000` file. Under root the read succeeds, the post-read size check fires,
and the R2 revert would pass. GitHub's runner is not root and the test killed R2 here, so this is a note
for anyone running the suite in a root container, not a defect.

Things I checked that hold: the read-list test's yardstick does not import the scanner's ignore list
(it asserts the two are equal instead); `bytes` is compared as well as `files`; the FIFO/socket test uses
real special files; the floors test requires every credential rule to be either floor-pinned or declared
unfloored, so a new rule cannot slip past it; the new failure messages print a count and the first
entries only, which keeps the ratchet's bounded child buffer from mistaking a failing suite for a dead
child; the scanner is still clean on its own tree.
