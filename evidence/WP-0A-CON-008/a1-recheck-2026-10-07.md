## 4. New finding

### N-3 (Medium, guard integrity; not stop-the-line) — the handoff guard never sees the last commit unless that commit is the handoff

`scripts/refresh-author-handoff.mjs --check` (and `test-kits/handoff-conformance.test.mjs`, which
imports the same functions) compares the cited head against `branchTipBefore()`, which for a
non-merge `HEAD` is **always `HEAD^`** — by design, "because a handoff cannot cite the revision that
contains it" (`evidence/WP-0A-CON-008/merge-parent-order.md`). Nothing checks that `HEAD` **is** the
handoff commit. So whatever the last commit carries is outside the comparison.

Measured on this branch: at `e601ea28`, whose handoff still cites `8526ca67` and which itself modifies
`work-packages/WP-0A-CON-008.json` (a substantive path), `check:handoff` exits **0** and the
conformance test passes 19 / 19. The done list's statement that `check:handoff` "will not pass until
the refresh" is **false as measured**. CI checks out the branch name (`ci.yml`, `ref: head_ref`) and
reads the same `HEAD^`, so CI would also be green on `e601ea28`. The 2026-09-15 record's "Every later PR
must keep the plumbing as its last commit … it is now enforced" holds only for the half where the
plumbing *is* last; a branch whose last commit is anything else passes unexamined.

Why A1 grades it: the handoff is where a package carries its open risks. A final commit that edits
or drops a risk record — the N-2 class exactly — or adds any substantive file, is merged with every
mechanical guard green and a handoff that does not describe it. The only control is reviewers reading
`git show --stat HEAD` by hand (R0's condition 4), which is what the guard was built to replace.

- **Owner:** WP-0A-CON-008 (its `writable_paths` hold `scripts/refresh-author-handoff.mjs`).
- **Fix sketch (owner decides):** when `HEAD` does not modify `handoffs/<package>-author-handoff.json`,
  compare the cited head against `HEAD` itself, not `HEAD^`; keep `HEAD^` only for the commit that
  carries the refresh. A negative-control test: a branch whose last commit changes a manifest and not
  the handoff must exit `DRIFTED`.
- **For this PR:** does **not** block the merge, because the plan is a last-and-alone refresh and R0
  checks it by hand. **Condition:** recorded as an `open_blockers` entry of this package (owner
  WP-0A-CON-008) before it leaves `in_review`; and the merge head is verified by `git show --stat HEAD`
  to touch only the handoff.
- I searched every `work-packages/*.json` `open_blockers` and this package's evidence for a record of
  this gap and found none.
