## 3. Probes (measured)

### Probe A: hostile configuration through every non-`GIT_` and `GIT_CONFIG_*` route

A script builds a `home/.gitconfig`, an `xdg/git/config` and a `sys.gitconfig`, each setting:
- `core.hooksPath` to 29 hooks
- `core.fsmonitor` to a program
- `core.attributesFile` with `* filter=probe`, and `filter.probe.clean`/`smudge`

`GIT_CONFIG_GLOBAL` and `GIT_CONFIG_SYSTEM` pointed at the probe files, `GIT_CONFIG_COUNT=2` (`core.hooksPath`,

## 4. The Q0-AUD1018-1 deflake, security view

The interrupt case now waits up to 2 s, in 20 ms polls, for the verifier pid to be gone, then makes the same
assertion. The index-restore and no-commit assertions still come first, unchanged. A gate that does not stop its
verifier still fails: the stub verifier's own timer is 60 s. The wait does open a window of at most 2 s in which a

`commit-when-clean.mjs` is unchanged (it kills the group and waits for `close`). Not a finding.

## 5. Findings

- **A1-296-1 (Info, against this PR, measured).** Probe A run against the whole ratchets-bite file marked 18 lines, all
  from one case: `test-kits/ratchets-bite.test.mjs`, "the commit gate verifies the tree it commits: a new file a guard
  refuses is refused before it is tracked". What happens:
  - The case's stub `gate-verifier.mjs` (written by this file) runs under `commit-when-clean.mjs`'s `VERIFIER_ENV`,
    which drops both settings.
  - It passes `process.env` on to `node --test test-kits/app-boundaries.test.mjs`.
  - That file's git, in its own temporary repository, then ran the caller's global `core.fsmonitor`, `filter.*` (via
    `core.attributesFile`) and `core.hooksPath` hooks.

  It is the same class and the same grade as A1-293-2/A1-294-3: the operator's own configuration, not a redirect into
  another repository. But it is in this PR's file, and the new case is meant to pin it, yet its rerun pattern
  `(?! verifies)` leaves this case out. The records also say more than holds:
  - `open_blockers[18]` says "it is the environment of every child each file starts". That is true of children, not
    of this grandchild.
  - It and the disposition say the verifier "is the suite, whose three files set them again". Here the verifier is a
    stub that runs `app-boundaries.test.mjs`, which sets nothing.

  Fix, within this package's file: set `GIT_CONFIG_NOSYSTEM=1` and `GIT_CONFIG_GLOBAL=/dev/null` in the `env` that
  `gate-verifier.mjs` builds, and make the config case cover this case too.
  Changing `VERIFIER_ENV` in `commit-when-clean.mjs` would also work. It changes the real gate's behaviour, so it
  needs its own decision. **Open; under the Owner's "no security finding open" condition it blocks an A0 press.**
- **A1-296-2 (Info, against the suite, not this PR).** `test-kits/app-boundaries.test.mjs`, `app-dependencies.test.mjs`
  and `branch-scope.test.mjs` start git without the two settings: `grep -c GIT_CONFIG_NOSYSTEM` gives 0 in each. A real
  `npm run commit` runs them under `VERIFIER_ENV`, so the operator's global configuration reaches their temporary
  repositories. `branch-scope` is in hand under WP-0A-A0-004 by the same Owner answer. The other two are outside the
  answer's four files. Recorded so the class is visible; it needs no change in this PR.
