## 3. Findings

### A1-266-1 (Informational): the classifier's fork check is given this checkout as both repositories

`auditLaneOf` passes `repo = headRepo = '(this checkout)'`, so the fork condition of the audit predicate is always met
inside the handoff guard. The comment says so. I looked for the bypass: a fork PR whose branch carries WP-0A-A0-001's
branch name. CI checks out `ref: ${{ github.head_ref }}` from the base repository and then asserts
`HEAD == github.event.pull_request.head.sha`; a fork's head SHA is not that branch's, so the job fails before any test
runs. And CI's lane step still runs the real fork check. No action required; recorded so a later CI change that drops
the SHA assertion is read against it.

### A1-266-2 (Informational): history is judged by its net diff

A substantive commit reverted before the audit file is invisible to the exemption. That is the same net-diff view the
lane classifier and the merge itself take, and what reaches `main` is audit files only, so nothing is admitted that the
merge would carry. No action required.
