## 3. Can the tests RFC §7 specifies be built as written? (read)

The judgement is **yes, in the main**. `FREEZE_LEVELS`, `MANIFEST_KEYS`, the shape checks on `declared_gaps` (exact keys, `id` pattern and uniqueness, closed lists, at least 80 characters), the coverage rule of §5.2, `DECLARED_GAP_DIGESTS` in both directions, the check that the index agrees, and the two `'Frozen'` → out-of-vocabulary reversal values can all be written as stated. I checked the §7.2 line citations. Catalog lines 66, 71 and 80, envelope lines 122 and 147, and JOB lines 150 and 153 each hold the assertion the RFC says they hold.

The RFC's no-op diagnosis is correct. `mustNotice` asserts that the suite fails after each reversal (`ratchets-bite.test.mjs` lines 234–252). A reversal that becomes a no-op therefore turns the suite **red**. It does not go silently green. So the value change of §7.1 (2) is needed before the first freeze PR, not just tidy.

The findings below are all **advisory**. None blocks this PR, which changes no test. Each is for the §7.1 author (this package) and the freeze increments to act on, or for an RFC amendment if the Owner wants the text exact.

- **Q0-A1. The new declared-gap reversals cannot be measured in the preparatory PR.** §7.1 (2) asks for three new reversals in that PR, "each measured": an `owner` emptied, a `closes_before` set outside the list, and one gap deleted. §7.1 also says that PR "changes no contract", so no manifest carries `declared_gaps` yet. An "emptied" or "deleted" reversal then has no target, and `mustNotice` fails because it found nothing to change. A reversal that first inserts a gap would be noticed for the wrong reason, because the gap is unpinned in `DECLARED_GAP_DIGESTS`. In the same way, the "a Frozen contract declares every gap…" test passes vacuously while no contract is Frozen. A JSON reversal that sets `status = 'Frozen'` is caught first by the per-contract status pin, not by the new rule. These reversals can only bite at the first manifest that carries a real declared gap. Recommendation: the §7.1 PR measures the new rules with `mustNoticeSourceEdit`-style probes or with synthetic fixtures under `test-kits/`, and moves the three JSON reversals to the first increment that adds `declared_gaps`. §4.3's Q0 row ("bite on this contract … measured") already puts per-contract measurement at the freeze, so the two sections can be reconciled without changing their intent.
- **Q0-A2. The catalog reversal's selector runs dry.** The reversal "a Candidate contract promoted to a level the register does not define" (`ratchets-bite` line 362) picks the first entry with `status === 'Candidate'`. Changing its value to `'Released'` fixes the value. Once no Candidate remains, the loop matches nothing and the reversal becomes a no-op again, and the suite goes red. This does not happen inside the First Slice, because CTR-USG-001 stays Candidate after the exit. It is still a dated trap. Recommendation: target a named contract, or any entry, not "the first Candidate".
- **Q0-A3. The "Draft only." check misses "Candidate only;".** The rule "`freeze_boundary` does not begin 'Draft only.'" (§4.1 (4), §7.1) would pass a Frozen CTR-TEN-001, CTR-ERR-001, CTR-EVT-001 or CTR-JOB-001 whose boundary still opens "Candidate only;", as all four do today. That text is equally stale after a freeze. C0 reads the restatement (§4.3), so this is not a hole in the gate, but the mechanical check is weaker than its stated purpose. Recommendation: reject both prefixes.
- **Q0-A4. Pins that move at a freeze are not all named.** `freeze_boundary` is digest-pinned per contract in `CAVEAT_DIGESTS` (`catalog-registry.test.mjs` lines 305–318). The index `freeze_boundary` is pinned in `INDEX_HEADER.freeze_boundary_digest` (line 621). Restating either one (§4.1 (4), §7.2 last bullet) moves that pin too. §4.5 names only "the registry pin". Both pins live in a `WP-0A-CON-008` file, so they belong in the same `amends_without_owning` entry. They should be named so that a freeze PR's scope declaration is complete.
- **Q0-A5. The census in §7.2 is incomplete.** These assertions also move, and §7.2 does not name them:
  - `shared-kernel-envelope-contracts.test.mjs` line 148 (exactly five Draft), line 150 (`PROMOTED` each Candidate: API, PAG, IDM, MOD, FLG) and line 153 (`AWAITING_CO_OWNER` each Draft: SEC, AUD, OBS, USG, NTF). Line 150 breaks at the first freeze of any of those five. Line 153 breaks at every Draft → Candidate step.
  - `tests/db/identity/identity-isolation.test.mjs` lines 6023 and 8004. Both assert that CTR-USG-001 is `Draft`, and both break when USG reaches Candidate under the Q-031-1 reading of §6.
- **Q0-A6. "Never reused" cannot be measured.** "Never reused" for a gap `id` (§5.2) cannot be measured from one tree: a deleted gap takes its pin with it. The RFC says this honestly about the pinned Candidate step (§7.1 (1), last bullet) but not here. Recommendation: either keep retired ids in the pin, or state that reuse is reviewed, not measured.
- **Q0-A7. Prose reads as before the approval (read; for C0 and R0, not a test matter).** The approval commit `e2ec50a8` did not touch `work-packages/WP-0A-CON-008.json`. So its new `outputs` line ("Proposed 2026-10-09"), `open_blockers[6]` ("status Proposed") and `open_blockers[8]` (item (1), "OWED … Owner: answers to Q-031-1 to Q-031-5") still describe the Proposed state. As dated entries they were true when written. The handoff at the head does say "Approved". I note this so the records transcription after the merge does not read [8] (1) as still owed.
