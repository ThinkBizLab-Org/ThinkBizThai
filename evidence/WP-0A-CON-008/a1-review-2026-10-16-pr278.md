## 3. Findings

### A1-278-1 — Medium (integrity), open; not stop-the-line

**On an index with unresolved conflicts, a refusal destroys the conflict state and git's own unmerged-path stop.**
`git write-tree` fails on such an index, so `restore()` has nothing to restore to; but `git add -A` has already run and
marked every conflicted path resolved, conflict markers included. Measured above: `git ls-files -u` goes from 3 entries
to 0; the stage-1/2/3 versions are gone (no `checkout --conflict` recovery); and the plain `git commit` that git refused
before the gate ran now succeeds with `<<<<<<<` in the committed file. `main`'s script never touched the index before the
verifier passed, so this is new with this PR. The comment and the refusal text say the changes "are left staged", which
does not say the conflicts were resolved. The gate is used on merges in this repository (the handoff records the merge
`ac1a347d` committed through it), and no repository guard scans for conflict markers.

Requested: when `git write-tree` fails (or `git ls-files -u` is non-empty), refuse **before** `git add -A` with its own
code and message and leave the index untouched; pin it with a case (a conflicted merge is refused, and `git ls-files -u`
is unchanged after the refusal), failing under the head's script.

### A1-278-2 — Info (advisory, not a security finding)

An interrupt or a tool timeout during the verifier (tens of seconds) now leaves every change staged, new files
included, where `main`'s script left the index untouched. The gate still cannot commit an unverified tree, and the next
gate run re-verifies whatever is staged; the residue matters only to a later plain `git commit`. Optional: restore on
`SIGINT`/`SIGTERM`, or record it under `known_limitations`.

### A1-278-3 — Info (advisory, pre-existing, not a security finding)

A write that lands between the first sample and `git add -A` and is reverted before the second sample is committed
without having been verified; `main`'s script has the same hole around its staging sample (probe above). The new
comment's "a write landing between the first sample and `git add` changes the tree, so the second sample refuses it"
holds only for a write that persists. Optional closer: after the second sample, require that the index equals the
working tree (`git diff --quiet` and no untracked, non-ignored file), which turns this into a refusal.

### A1-278-4 — Info (advisory)

Only the verifier-failure refusal's restore is pinned by a suite case. The restores on 90, 92 and a failing `git add -A`
are correct by my probe but unpinned; a case per path would keep them so.

### A1-278-5 — Info (press condition, not a verdict input)

CI on `83274247` was pending at reading time (`bootstrap`, run `38844276564`). The Owner's answer requires green on both
jobs before A0 presses.
