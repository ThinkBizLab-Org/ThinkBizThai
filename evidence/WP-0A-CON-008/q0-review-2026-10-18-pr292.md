## 6. Findings

- **Q0-292-1 (Low, test strength): "stops its verifier" is not pinned.** The interrupt case's comment says "it is the
  gate that has to stop the verifier", but with the kill removed (m05) or the verifier not in its own group (m07) the
  case still passes: the probe verifier exits by itself after 60 s, the gate then restores and exits 143, and
  `stillRunning(verifierPid)` is false by then. The behaviour is right at the head (§3 probes: 31–33 ms), so this is
  a missing bound, not a defect. A time bound on the gate's exit after the signal (well under the verifier's own
  timer), or a verifier that never exits by itself, would kill both mutants. Not blocking; A0's to fix or record.
- **Q0-292-2 (Low, class beyond this PR; for A1 to grade): other test files still inherit `GIT_*`.**
  `ci-guard-behaviour`, `branch-scope`, `handoff-conformance` and `app-boundaries` spawn `git` with the inherited
  environment. Run with `GIT_INDEX_FILE` and `GIT_OBJECT_DIRECTORY` pointed at a throwaway "caller" repository:
  `ci-guard-behaviour` **passes (17/17) while changing 36 files** under the caller's `.git`; `branch-scope` (80
  files) and `handoff-conformance` (149 files) change it and fail; `app-boundaries` changes nothing. The PR's claim
  is scoped to `ratchets-bite.test.mjs` and is accurate as worded, and the PR states as a residual that the gate
  honours its own caller's `GIT_*`. The two combine, though: a gate run from a pre-commit hook passes the hook's
  `GIT_INDEX_FILE` to `npm run verify`, whose full suite then reaches the index being committed through these files.
  Not blocking this PR; a follow-up for the class.
- **Q0-292-3 (Info): unpinned but probed paths.** m06, m08, m11, m12, m13, m14 survive the suite. m08 is close to
  equivalent on refusal paths (the restore writes the found bytes back over any refresh); m13 (escalation) and the
  linked-worktree, `GIT_INDEX_FILE`, absent-index and SIGINT/SIGHUP paths are right by probe (§3) but no case pins
  them. Recorded so a later edit knows the suite will not notice.
- **Q0-292-4 (Info, wording): a stale `index.lock` is reported as "unresolved conflicts or cannot be recorded".**
  `git write-tree` fails on the lock, so the gate refuses 95 before staging, index and lock untouched — correct and
  safe; the message does not name the lock.
