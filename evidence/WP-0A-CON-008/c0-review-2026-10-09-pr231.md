## 5. Findings

All are advisory. None blocks this verdict or a delegated press.

- **A-1. The boundary check is wider than §7.1's text.**
  - §7.1 says "`freeze_boundary` does not begin 'Draft only.'". The test also rejects "Candidate only". It also
    tolerates leading whitespace and does not require the period.
  - The addition comes from Q0-A3. It is grounded in §4.1 (4), "It must say what the frozen contract does and does
    not settle", and it is disclosed in the prep record §3 and in `[9]`.
  - It can only make a freeze increment restate a boundary that §4.1 (4) already requires to be restated. So I read
    it as conforming in purpose.
  - It should be named in the next RFC-2026-031 amendment so that the RFC and the test say the same thing.
- **A-2. `RETIRED_DECLARED_GAP_IDS` adds a step that §5.4 does not state.**
  - §5.4: closing a gap "removes its entry and cites the closing evidence in the same commit". The test also requires
    the closer to move the id to the retired list. Otherwise the pin test reports a drop.
  - This implements §5.2's "Never reused" (my A-8, Q0-A6), and it is the measurable form.
  - The step should go into the same RFC amendment as A-1 and my A-8's open rules. A closer reading only §5.4 would
    otherwise meet a red pin test.
- **A-3. "Characters" is measured as UTF-16 length after `trim()`.**
  - Whitespace padding does not count, which is stricter than the RFC's words.
  - Thai text is all in the Basic Multilingual Plane, and combining marks count one each. So `.length` is a fair
    reading of "characters".
  - The prep record discloses the trim. Recorded for completeness.
- **A-4. §7.1 (2)'s three JSON reversals are substituted for now and deferred.**
  - The RFC asks for "New reversals, each measured: a declared gap's `owner` emptied; its `closes_before` set outside
    the list; one gap deleted". At this head no manifest carries a gap, so a JSON reversal has nothing to change (Q0-A1).
  - The PR measures the same three rules with synthetic controls, and with a source-reversal case in
    `ratchets-bite.test.mjs` (owner check, gate check, pin drop direction, plus two more). It leaves the JSON form to
    the first increment that adds `declared_gaps`.
  - That deferral is recorded with an owner in `[9]` OWED (4), in prep §4 (the freeze-increment table) and in prep §5.
    It is consistent with §4.3's Q0 row ("bite on this contract … measured").
  - It is a departure from §7.1 (2)'s letter that the RFC does not authorise. It needs no Owner question, because the
    deferred reversals land in a later reviewed PR. The first freeze increment's C0 must check that they do.
- **A-5. One half of `source` resolution is not measured.**
  - §7.1: `source` resolves to "a manifest field that is present". I replaced
    `(DECLARED_GAP_SOURCE_FIELDS.includes(source) && nonEmpty(manifest[source]))` with
    `DECLARED_GAP_SOURCE_FIELDS.includes(source)`. With that reversal `catalog-registry.test.mjs` still exits 0.
  - The synthetic violations cover a source naming a field outside the list (`trust_boundary`), but not a listed
    field that is absent, for example `source: 'untestable_by_schema'` on a manifest without it.
  - The rule itself is implemented correctly. The comment "every rule is ALSO run against synthetic manifests" slightly
    overstates the measurement.
  - One more synthetic violation would close it, in this PR or the first increment that adds `declared_gaps`. It is not
    blocking: no manifest carries a gap, and the §7.1 (2) list does not include this rule.
- **A-6. #229's status record is folded into a full-path increment.**
  - R0 §9 says "Put them in the post-merge records PR of WP-0A-CON-008" and "The status line of the same records PR is
    `in_review` to `integration_verified`".
  - This PR carries the words and the status move as prose in `[9]` (A). It then returns the package to `in_review`
    for its own increment (`[9]` (B)), so the `status` field reads `in_review` before and after.
  - That follows the WP-0A-A0-002 (#204) and WP-0A-CON-004 (#210) precedent. The words are R0's and are byte-exact.
  - One consequence: #229's records reach `main` only when this tier-H PR merges. R0 should say whether this placement
    satisfies its §9. The transcription file §4 also leaves the handoff press-basis reading to R0.
