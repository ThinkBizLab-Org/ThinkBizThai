## 2. Do the declared-gap tests enforce RFC §5.5, or only its shape?

**Only the shape.** None of the new rules can tell a tenant-isolation gap, an open A1 finding or a missing
`required_before_freeze` item from any other gap. The `kind` list (`runtime`, `schema`, `accepted-fixture`,
`decision`) has no tenant or security value, and `A1` is on the closed owner list. Because `freeze_boundary` is a
valid `source` and every manifest has a non-empty boundary, any prose can be anchored to it. My probe in §1 declared
a cross-tenant read on a Frozen CTR-TEN-001, and every new rule passed it. A tenant-isolation gap **can** be declared
and pass the tests.

**Is this a finding against this PR? No.**
- RFC-2026-031 §7.1 lists the mechanical checks it asks for: shape, closed lists, length, source, pin, and coverage at
  Frozen. §5.5 is not among them.
- §4.3 gives §5.5 to the A1 freeze review by name: "that no declared gap is a security gap the Owner did not accept
  (§5.5). An A1 finding of any grade blocks the freeze".
- §4.1 (2) and (6) make the other two kinds preconditions that a signature and A1 check.
- Whether some prose describes a tenant-boundary crossing is a judgement about meaning. No closed list can measure it
  without inventing a taxonomy the RFC did not approve.

So the PR does what §7.1 asks. The real control for §5.5 is the per-contract freeze review, and A1 holds it. **A1
commits to the following in every freeze review:** read each `declared_gaps` entry, and the item its `source` points
to, against the three kinds in §5.5. A gap of any of those kinds is a finding that blocks the freeze, whatever its
`kind`, `owner` or gate.

**F-1 (advisory).** The new test file says the Draft → Frozen pin history is "reviewed, not measured". It says
nothing like that about §5.5. A future reader could take a green "a Frozen contract declares every gap" as proof
that §5.5 holds. Recommended: one comment next to `DECLARED_GAP_KINDS` or `frozenProblems()` that says §5.5's three
undeclarable kinds are not measured and are checked by the A1 freeze review (§4.3). The comment can land in this PR
or in the first freeze increment. It is not a condition of this PR.

## 3. Do the ratchet changes weaken an existing guard?

**No.**
- **Floors only go up.** In `scripts/test-suite-contract.mjs`, catalog-registry goes from 15 to 19 tests and from 19
  to 28 assertions, and ratchets-bite goes from 19 to 20 tests. No floor goes down. The two name digests move
  because tests were added. The diff renames or removes no existing test.
- **The two reversals move from `'Frozen'` to `'Released'`.** Before this PR, `'Frozen'` was outside
  `FREEZE_LEVELS`, so these reversals were caught either by the vocabulary check or by the pin. `'Released'` is
  caught in the same two ways. Coverage is the same, and RFC §7.1 (2) asks for this move. The catalog reversal now
  names CTR-ERR-001 instead of "the first Candidate". That is stronger, because it cannot run out of targets.
- **The risk this PR creates** is that `Frozen` is now a legal value, so an unpinned promotion is stopped only by
  the per-contract pin and the index and Frozen rules. I measured that this promotion still fails three tests (§1).
- **F-2 (advisory).** No reversal in `ratchets-bite.test.mjs` now measures that exact path: a named Candidate set to
  the now-legal `'Frozen'` with no pin edit. Before this PR, the old `'Frozen'` reversal did that implicitly. My
  probe shows the protection holds today, but the suite no longer requires it to. Recommended: one named reversal,
  for example CTR-ERR-001's manifest set to `'Frozen'`, kept until ERR itself is pinned Frozen. The RFC chose
  `'Released'`, so this is a suggestion, not a condition.
- **The new source-reversal case** strips five rules in a copy and requires the synthetic controls to fail. It adds
  coverage and removes none. The synthetic `CTR-ZZZ-001` is built in memory and never written to the catalog.
- **`blockerExistsOnDisk(wp, n)`** builds a path from a regex capture that is limited to `[0-9A-Z-]` after `WP-`.
  It cannot traverse paths.
